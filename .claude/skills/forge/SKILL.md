# Навык forge

Единственная точка входа LLM в Liquibase Forge: начинает операцию по намерению либо продолжает
открытую, исполняет её беклог и возвращает итоговый отчёт; по просьбе владельца бросает открытую
операцию. Понятия — в `docs/domain.md`,
команды CLI — в `docs/operation.md` и `docs/architecture.md`.

## Вызов

```text
/forge <намерение> [--mode interactive|auto] [--allow-drop]
/forge --abandon "<причина>"
```

- **Намерение** — текст, описывающий желаемое изменение модели данных. Обязательно для новой
  операции; при открытой операции не принимается.
- **`--mode`** — `interactive` по умолчанию: стоп-знаки перед созданием модели, накатом
  и закрытием. `auto` — автоматические гейты вместо стоп-знаков, допустим только для тестовой БД.
- **`--allow-drop`** — согласие операции на удаление таблиц и колонок, только для режима `auto`:
  без согласия удаления в `auto` отклоняет `forge generate`, и операция останавливается. Ключ
  даёт согласие новой операции вместе с `--mode auto` либо остановленной операции в `auto`
  при продолжении. В `interactive` ключ не нужен — стоп-знак перед накатом показывает удаления.
- **`--abandon "<причина>"`** — бросить единственную открытую операцию: откатить её начатые
  попытки и закрыть статусом `abandoned`, ничего не принимая. Сам вызов с ключом — решение
  владельца, поэтому стоп-знака нет ни в `interactive`, ни в `auto`. Ключ принимается только
  отдельно: вместе с намерением, `--mode` или `--allow-drop` он отклоняется.

Все команды выполняются из корня проекта. CLI `forge` запускается обёрткой
`tools/forge-env/forge.sh` — одинаково в репозитории forge и в проекте, куда forge установлен,
поэтому команда `forge …`, названная в беклоге, выполняется как `sh tools/forge-env/forge.sh …`.

## Правила

- Статус операции меняет только CLI `forge`: `forge stop`, `forge resume`, `forge close`,
  `forge abandon`.
  Фронтматтер беклога агент правит только там, где это прямо предписывает задача беклога.
- Одновременно открыта не больше одной операции.
- Код `2` любой команды `forge` — ошибка окружения, а не неуспех попытки: открытую операцию
  остановить `forge stop` с диагностикой в причине, LLM вернуть диагностику. Исключение —
  `forge abandon`: операцию бросают, а не останавливают, поэтому LLM получает только диагностику.
- Бросить операцию навык может только по ключу `--abandon`, по собственному решению — никогда.
- Решений, которые принимает CLI (развилка попыток, исход закрытия, допустимость удаления),
  навык не принимает.
- Признак `allow_drop` задаётся при начале операции либо даётся остановленной операции в `auto`;
  снять его нельзя, исполняемой операции (`running`) ключ не меняет.

## Порядок

1. Если передан `--abandon`:
   - вместе с намерением, `--mode` или `--allow-drop` — сообщить LLM: «ключ `--abandon`
     принимается только отдельно», ничего не вызывать и остановиться;
   - иначе выполнить [отказ](#отказ) и остановиться.
1. Убедиться, что доступен CLI плагина `formular`: `backlog --help`. Если команды нет в `PATH`,
   взять `~/.claude/plugins/cache/formular/backlog/<версия>/bin/backlog` наибольшей версии;
   если нет и его — вернуть LLM: «плагин `backlog@formular` не установлен», и остановиться.
1. Проверить среду и найти открытую операцию: `sh tools/forge-env/forge.sh status --latest`.
   - Код `2` — вернуть LLM перечень непройденных проверок `environment` либо ошибку
     и остановиться.
1. Если `operation` не `null`, продолжить её:
   - если намерение передано, сообщить LLM: «открыта операция `<path>`, новое намерение
     не принято; продолжаю открытую»;
   - если передан `--allow-drop`, решить по режиму и статусу открытой операции из ответа:
     - `auto` и `stopped` — продолжить с согласием:
       `sh tools/forge-env/forge.sh resume --operation <path> --allow-drop`;
     - `auto` и `running` — сообщить LLM: «ключ `--allow-drop` не принят: операция исполняется,
       признак `allow_drop` не меняется»;
     - `interactive` — сообщить LLM: «ключ `--allow-drop` действует только в режиме `auto`;
       в `interactive` удаления разрешены без него» и продолжить без согласия;
   - если операция `stopped` и согласие не дано — `sh tools/forge-env/forge.sh resume --operation <path>`;
   - перейти к шагу 5 с беклогом `<path>`.
1. Иначе начать новую операцию:
   - если передан `--allow-drop` без `--mode auto`, сообщить LLM: «ключ `--allow-drop` действует
     только в режиме `auto`», беклог операции не порождать и остановиться;
   - штамп — `date -u +%Y%m%d-%H%M%S`;
   - `backlog generate --operation forge-model --subject <штамп> --value intent=<намерение>`,
     `--flag auto` при режиме `auto` либо `--no-flag auto` при `interactive`, и `--flag allow-drop`
     при ключе либо `--no-flag allow-drop` без него;
   - беклог операции — `backlog/forge-model/<штамп>/tasks.md`.
1. Загрузить носитель порядка `/backlog:backlog-run` и исполнить беклог операции. Беклоги попыток
   порождает и исполняет сам беклог операции.
1. Когда исполнение завершено или остановлено, вернуть LLM вывод
   `sh tools/forge-env/forge.sh report --operation <беклог операции>`. При статусе `success`
   или `failure` назвать файлы для коммита из `commit.files` отчёта: след операции, а при `success` — и файлы
   корня принятого состояния. Перечень не вычислять и не сокращать, коммит делает владелец.

## Отказ

Порядок по ключу `--abandon "<причина>"`:

1. Найти открытую операцию: `sh tools/forge-env/forge.sh status --latest`.
   - Код `2` — вернуть LLM диагностику и остановиться.
   - `operation: null` — сообщить LLM: «открытой операции нет, бросать нечего», команд, меняющих
     статус, не вызывать и остановиться.
1. Бросить её: `sh tools/forge-env/forge.sh abandon --operation <path> --reason "<причина>"`.
   - Код `0` — операция брошена, начатые попытки откатаны.
   - Код `1` — бросить нельзя: откат попытки не подтверждён. Операция остаётся открытой; вернуть
     LLM причину `refused` вместе с отчётом из следующего шага.
   - Код `2` — вернуть LLM диагностику без `forge stop` и остановиться.
1. Вернуть LLM вывод `sh tools/forge-env/forge.sh report --operation <path>`. Для статуса `abandoned`
   назвать файлы для коммита из `commit.files` отчёта — след операции и её начатых попыток;
   файлов корня принятого состояния среди них нет. Следующий вызов навыка с намерением начинает
   новую операцию.
