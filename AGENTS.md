Точка входа инструкций для агентов, работающих в репозитории: откуда читать правила оформления
и процесса и какие документы описывают сам forge. Правила приходят из плагина tessera и
в репозиторий не копируются; применение forge описано в [`README.md`](./README.md).

## Правила кода

Перед выполнением любой задачи агент обязан полностью прочитать все правила, перечисленные ниже.

Правила лежат в установленном плагине tessera, в каталоге `rules/` его поставки, и читаются через
навык-каталог `tessera-plugin`: названный код правила (`DOC-014`, `READ-004`, `ENV-006`) или тема
возвращают само правило и путь к нему в поставке.

| Правило | О чём |
|---------|-------|
| Документация (`documentation-rules.md`) | Язык, формат Markdown, структура, версионирование документов |
| Чтение документов (`reading-rules.md`) | Гейт чтения, запрещённые каталоги, границы контекста задачи |
| Окружение (`environment.md`) | Единый стандарт: mise — единственный менеджер инструментов, задач и демонов сервисов, фиксированные порты и паттерн переменных |
| Чистая архитектура (`clean-architecture.md`) | Направление зависимостей между слоями, состав слоёв, SOLID, модульная организация |
| CQRS (`cqrs.md`) | Разделение контрактов чтения и записи, принадлежность контрактов слоям |
| Domain Driven Design (`ddd.md`) | Единый язык, ограниченный контекст, агрегат, сущность, объект-значение, доменное событие |
| Документы проекта (`project-docs-rules.md`) | Роли, каркас и голос `README.md`, `CONTRIBUTING.md` и документа кейсов, блок бейджей `README.md` |

## Процесс разработки

- Git (`git-rules.md`) — именование веток, формат сообщений коммитов, границы безопасности git-операций.

Служебные подписи об авторстве или генерации любых LLM-агентов и инструментов не добавляются
в сообщения коммитов и описания PR/MR — правило `GIT-012`.

Изменения поведения ведутся через OpenSpec: предложение, реализация и архивация изменения —
навыки `openspec-propose`, `openspec-apply-change` и `openspec-archive-change`.

## Локальная настройка

Каталоги регистрации харнесов `.claude/` и `.zcode/` находятся вне индекса git — их содержимое
разработчик создаёт сам под свои инструменты.

1. Правила — плагин tessera. Харнес с маркетплейсами плагинов ставит его из маркетплейса
   `united-software-platform/tessera`; харнес без поддержки плагинов — клон репозитория tessera
   и `scripts/bootstrap.sh <каталог навыков проекта>` в нём.
1. Инструменты — `mise install`, затем `uv sync --frozen`: окружение `.venv` ставит CLI `forge`
   на `PATH` оболочки с активированным mise.
1. Навыки OpenSpec разворачивает `openspec init` под выбранные харнесы; каталог `openspec/`
   со спецификациями уже лежит в репозитории и от инициализации не зависит:

   ```bash
   mise exec -- openspec init --tools <список-харнесов> --language ru --scope project
   ```
