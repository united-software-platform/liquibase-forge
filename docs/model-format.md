## Назначение и границы

Модель данных описывает **полное целевое состояние** схемы `public`, а не изменение. Changelog
строится как разница между принятой моделью `db/model.yaml` и моделью попытки: новые и удалённые
таблицы, колонки и ограничения.

Версия `1` формата покрывает ядро модели: таблицы, колонки, типы, первичный ключ (Primary Key, PK),
обязательность (NOT NULL), наборы уникальности и внешние ключи (Foreign Key, FK) между таблицами.
Поля `unique` и `foreign_keys` необязательны: модель без них корректна, как и до их появления.
Так же необязательны поля колонки `generated` — [генерация значения](#генерация-значения) —
и `check` — [перечень значений](#перечень-значений).

## Пример

```yaml
version: 1
tables:
  - name: customer
    columns:
      - name: id
        type: uuid
      - name: email
        type: string
        length: 255
        nullable: false
      - name: full_name
        type: text
      - name: created_at
        type: timestamp_tz
        nullable: false
    primary_key: [id]
    unique:
      - [email]
  - name: invoice_line
    columns:
      - name: invoice_id
        type: bigint
      - name: line_no
        type: integer
      - name: amount
        type: decimal
        precision: 12
        scale: 2
        nullable: false
      - name: is_paid
        type: boolean
      - name: due_date
        type: date
      - name: created_at
        type: timestamp
      - name: customer_id
        type: uuid
    primary_key: [invoice_id, line_no]
    foreign_keys:
      - columns: [customer_id]
        references: {table: customer, columns: [id]}
```

Пример хранится также в `tests/fixtures/model/example.yaml`: тест проверяет, что блок выше
совпадает с файлом и что модель корректна.

## Структура файла

Файл — YAML-документ в UTF-8, корень — отображение. Других полей, кроме перечисленных, нет:
неизвестное поле — нарушение.

| Путь | Поле | Обязательно | Значение |
|------|------|-------------|----------|
| корень | `version` | да | Целое число `1` |
| корень | `tables` | да | Список таблиц, может быть пустым |
| `tables[N]` | `name` | да | Имя таблицы |
| `tables[N]` | `columns` | да | Список колонок, хотя бы одна |
| `tables[N]` | `primary_key` | да | Список имён колонок PK, хотя бы одно |
| `tables[N]` | `unique` | нет | Список [наборов уникальности](#уникальность), по умолчанию пуст |
| `tables[N]` | `foreign_keys` | нет | Список [внешних ключей](#внешние-ключи), по умолчанию пуст |
| `tables[N].unique[K]` | — | — | Список имён колонок набора |
| `tables[N].foreign_keys[K]` | `columns` | да | Список имён колонок FK своей таблицы |
| `tables[N].foreign_keys[K]` | `references` | да | Цель: отображение с полями `table` и `columns` |
| `tables[N].foreign_keys[K].references` | `table` | да | Имя целевой таблицы модели |
| `tables[N].foreign_keys[K].references` | `columns` | да | Список имён колонок цели |
| `tables[N].columns[M]` | `name` | да | Имя колонки |
| `tables[N].columns[M]` | `type` | да | Тип из [перечня](#типы-колонок) |
| `tables[N].columns[M]` | `nullable` | нет | `true` или `false`, по умолчанию `true` |
| `tables[N].columns[M]` | `length` | для `string` | Целое число |
| `tables[N].columns[M]` | `precision` | для `decimal` | Целое число |
| `tables[N].columns[M]` | `scale` | для `decimal` | Целое число |
| `tables[N].columns[M]` | `generated` | нет | Строка `identity` — [генерация значения](#генерация-значения) |
| `tables[N].columns[M]` | `check` | нет | Список значений — [перечень значений](#перечень-значений) |

Порядок таблиц и колонок сохраняется, но для схемы смысла не несёт. Порядок колонок
в `primary_key` значим. Порядок наборов `unique`, внешних ключей и колонок в наборе смысла
не несёт; в FK порядок задаёт только пары «колонка FK → колонка цели».

## Типы колонок

Типы формата не совпадают с типами СУБД. Отображение в PostgreSQL выполняют построение changelog
и сверка.

| Тип | Параметры | Допустимые значения | PostgreSQL |
|-----|-----------|---------------------|------------|
| `integer` | — | — | `integer` |
| `bigint` | — | — | `bigint` |
| `boolean` | — | — | `boolean` |
| `string` | `length` | от 1 до 10485760 | `varchar(length)` |
| `text` | — | — | `text` |
| `decimal` | `precision`, `scale` | `precision` от 1 до 1000, `scale` от 0 до `precision` | `numeric(precision, scale)` |
| `date` | — | — | `date` |
| `timestamp` | — | — | `timestamp without time zone` |
| `timestamp_tz` | — | — | `timestamp with time zone` |
| `uuid` | — | — | `uuid` |

Параметр, не относящийся к типу колонки, — нарушение: у `integer` нет `length`.

## Имена таблиц и колонок

Имена пишутся без кавычек и подчиняются общим правилам:

- шаблон `^[a-z][a-z0-9_]{0,62}$`: строчная латинская буква, затем строчные буквы, цифры и `_`;
- не зарезервированное слово PostgreSQL: `order`, `user`, `table` и другие из перечня
  `pg_get_keywords()` с категориями `R` и `T`;
- имена таблиц уникальны в модели, имена колонок — в пределах таблицы.

Дополнительные правила для таблиц и колонок:

| Объект | Правило | Причина |
|--------|---------|---------|
| Таблица | Не длиннее 60 символов | Имя PK `pk_<таблица>` должно уложиться в предел PostgreSQL 63 символа |
| Таблица | Не `databasechangelog` и не `databasechangeloglock` | Это таблицы журнала Liquibase |
| Колонка | Не `tableoid`, `xmin`, `cmin`, `xmax`, `cmax`, `ctid` | Это системные колонки PostgreSQL |

Схема БД всегда `public`, в модели она не указывается.

## Первичный ключ и NULL

- `primary_key` — непустой список имён колонок той же таблицы без повторов.
- Колонки PK всегда NOT NULL, `nullable` у них можно не указывать.
- Явное `nullable: true` у колонки PK — нарушение `primary_key_nullable`.
- Колонка вне PK без `nullable` допускает NULL.
- Колонка с `generated` всегда NOT NULL, как колонка PK.

## Уникальность

Элемент `unique` — набор колонок, значения которых вместе не повторяются в таблице:

- набор — непустой список имён колонок той же таблицы без повторов;
- набор отождествляется по составу: `[a, b]` и `[b, a]` — один набор;
- набор не совпадает по составу с PK таблицы: уникальность PK уже гарантирована;
- набор не повторяет другой набор той же таблицы.

```yaml
unique:
  - [email]
  - [tenant_id, code]
```

## Внешние ключи

Элемент `foreign_keys` связывает колонки своей таблицы с ключом целевой таблицы:

```yaml
foreign_keys:
  - columns: [customer_id]
    references: {table: customer, columns: [id]}
```

- `columns` и `references.columns` — непустые списки без повторов равной длины; колонки образуют
  пары по позиции.
- Колонки FK есть в своей таблице, целевая таблица — в модели, колонки цели — в целевой таблице.
- Колонки цели совпадают по составу с PK целевой таблицы или с одним из её наборов `unique`;
  порядок колонок цели для совпадения не важен: FK `[line_no, invoice_id]` на PK
  `[invoice_id, line_no]` корректен.
- Тип каждой колонки FK с параметрами совпадает с типом парной колонки цели: `bigint` не ссылается
  на `integer`, `string(100)` — на `string(255)`.
- FK с теми же парами колонок и целью не повторяется в таблице.
- Целевая таблица может стоять в модели ниже своей таблицы, быть той же таблицей, а ссылки могут
  образовывать цикл.

Других полей у FK нет: действие при удалении и изменении (`on_delete`, `on_update`) —
нарушение `unknown_field`, ограничение создаётся с действием `NO ACTION`.

## Генерация значения

Поле `generated: identity` поручает выдачу значения колонки БД: колонка становится
`GENERATED BY DEFAULT AS IDENTITY`. Вставка без значения получает следующее значение
последовательности, вставка с явным значением тоже допускается — так seed наполняет справочники
с явными ключами.

```yaml
version: 1
tables:
  - name: event
    columns:
      - name: id
        type: bigint
        generated: identity
      - name: payload
        type: text
    primary_key: [id]
```

- Единственное значение поля — `identity`; другая строка — нарушение `unknown_generation`.
- Тип колонки — `integer` или `bigint`, иначе `generated_requires_integer`.
- Колонка всегда NOT NULL: `nullable` можно не указывать, явное `nullable: true` — нарушение
  `generated_nullable`.
- Генерация задаётся не больше чем одной колонке таблицы: вторая и следующие —
  `duplicate_generated`. Входить в PK колонка не обязана, но это обычный случай.

Генерацию нельзя включить или снять у колонки принятой модели: `forge generate` отклонит такое
изменение кодом `column_generated_changed` — см. [migration.md](./migration.md#неподдерживаемые-изменения).
Новая колонка с генерацией в существующей таблице разрешена: БД заполнит значения существующих строк.

## Перечень значений

Поле `check` ограничивает значения колонки перечнем: колонка получает ограничение
`CHECK (<колонка> IN (…))`.

```yaml
version: 1
tables:
  - name: event
    columns:
      - name: id
        type: bigint
      - name: source
        type: string
        length: 16
        nullable: false
        check: [collector, manual]
      - name: priority
        type: integer
        check: [1, 2, 3]
    primary_key: [id]
```

- Перечень — непустой список без повторов: пустой список — `check_empty`, повтор —
  `check_duplicate_value` с путём повторного элемента.
- Перечень отождествляется по множеству значений: `[collector, manual]` и `[manual, collector]` —
  один перечень.
- Перечень допустим у типов `string`, `text`, `integer` и `bigint`, у остальных —
  `check_unsupported_type`.
- У `string` и `text` значения — строки YAML, у `string` не длиннее `length`. У `integer`
  и `bigint` — целые числа YAML в пределах типа. Значение не того вида — `check_value_wrong_kind`,
  выход за длину или диапазон — `check_value_out_of_range`. Логическое значение не считается целым.
- Перечень не задаётся колонке с `generated`: `check_with_generated`.
- Колонка с перечнем без `nullable: false` допускает NULL: `CHECK` в PostgreSQL пропускает NULL.

## Проверка модели

Команда `forge validate --model <путь>` печатает один JSON-объект:

```json
{
  "model": "backlog/forge-model/20261017-153000/attempt-1/model.yaml",
  "valid": false,
  "violations": [
    {"path": "tables[0].columns[1].length", "code": "missing_type_parameter", "message": "у типа string обязателен length"}
  ]
}
```

| Код возврата | Когда |
|--------------|-------|
| `0` | Нарушений нет, `valid: true` |
| `1` | Есть нарушения, `valid: false` |
| `2` | Файл не прочитать: его нет, это каталог, нет прав, не UTF-8; ответ — объект `error` с видом `model_unreadable` |

Проверка идёт в два уровня:

1. **Структура.** Вид значений, состав полей, повторные ключи, версия формата.
1. **Смысл.** Имена, типы и параметры, генерация и перечни значений колонок, уникальность имён,
   первичный ключ, наборы уникальности.
1. **Связи.** Внешние ключи — после всех таблиц: цель FK должна быть собранной таблицей.

Команда возвращает все нарушения сразу: сначала структурные в порядке документа, затем смысловые
по таблицам в порядке документа, затем нарушения FK по таблицам и FK в порядке документа. Внутри
таблицы смысловые нарушения идут в устойчивом порядке: повтор имени таблицы, имя таблицы, колонки,
PK, собственные нарушения наборов уникальности, повторы колонок, ссылки PK, NULL у колонок PK,
ссылки наборов, совпадение наборов с PK и их повторы. Внутри FK — колонки FK, целевая таблица, колонки цели, число колонок, ключ
цели, типы пар, затем повторы FK таблицы. Повторная проверка того же файла даёт тот же ответ.

Нарушение одного элемента не останавливает проверку остальных, но есть пять исключений:

- **Нарушение корня.** Корень не отображение, нет `version` или `tables`, версия не `1`:
  проверка останавливается на корне.
- **Структурное нарушение таблицы или её колонки.** Таблица не проверяется по смыслу, остальные
  таблицы проверяются полностью.
- **Некорректная колонка или PK.** Правила таблицы — уникальность колонок, ссылки PK, NULL
  у колонок PK, ссылки и повторы наборов уникальности — проверяются после исправления.
- **Некорректная таблица как цель или источник FK.** Таблица со структурными или смысловыми
  нарушениями целью не служит: FK на неё и её собственные FK проверяются после её исправления.
- **Некорректный список или имя в FK.** Имя колонки или таблицы FK, не проходящее правила имён,
  сообщается как ссылка на отсутствующий объект; пустой список, повтор колонки или разное число
  колонок останавливают проверку этого FK. Ссылки, ключ цели и типы проверяются после исправления.

Путь нарушения ведёт от корня файла: `tables[0].columns[1].length`, `tables[2].primary_key[1]`.
Пустой путь означает весь документ.

## Коды нарушений

Коды — часть контракта команды, сообщения могут меняться.

| Код | Уровень | Когда |
|-----|---------|-------|
| `yaml_syntax` | структура | Файл не разбирается как YAML или содержит несколько документов; в сообщении строка и столбец |
| `duplicate_key` | структура | Ключ повторён в одном отображении |
| `missing_field` | структура | Нет обязательного поля |
| `unknown_field` | структура | Поле не входит в формат |
| `wrong_kind` | структура | Значение не того вида: строка вместо списка, логическое вместо числа, пустой файл |
| `unsupported_version` | структура | `version` не равно целому `1` |
| `invalid_identifier` | смысл | Имя не соответствует шаблону или длиннее предела |
| `reserved_identifier` | смысл | Зарезервированное слово, системная колонка или таблица журнала Liquibase |
| `duplicate_name` | смысл | Повтор имени таблицы в модели или колонки в таблице; путь — повторное вхождение |
| `empty_columns` | смысл | У таблицы нет колонок |
| `unknown_type` | смысл | Тип вне перечня |
| `missing_type_parameter` | смысл | Нет обязательного параметра типа |
| `unexpected_type_parameter` | смысл | Параметр не относится к типу |
| `type_parameter_out_of_range` | смысл | Значение параметра вне допустимого диапазона |
| `empty_primary_key` | смысл | `primary_key` пуст |
| `primary_key_unknown_column` | смысл | PK ссылается на отсутствующую колонку |
| `primary_key_duplicate_column` | смысл | Колонка повторена в PK |
| `primary_key_nullable` | смысл | У колонки PK явное `nullable: true` |
| `empty_unique` | смысл | Набор `unique` пуст |
| `unique_unknown_column` | смысл | Набор ссылается на отсутствующую колонку |
| `unique_duplicate_column` | смысл | Колонка повторена в наборе |
| `unique_equals_primary_key` | смысл | Набор совпадает по составу с PK таблицы |
| `unique_duplicate` | смысл | Набор повторяет другой набор таблицы; путь — повторное вхождение |
| `empty_foreign_key` | связи | `columns` или `references.columns` FK пуст |
| `foreign_key_unknown_column` | связи | FK ссылается на отсутствующую колонку своей таблицы |
| `foreign_key_duplicate_column` | связи | Колонка повторена в `columns` или `references.columns` |
| `foreign_key_unknown_table` | связи | Целевой таблицы нет в модели |
| `foreign_key_unknown_target_column` | связи | В целевой таблице нет колонки цели |
| `foreign_key_column_count` | связи | Число колонок FK и цели различается |
| `foreign_key_target_not_key` | связи | Колонки цели не PK и не набор `unique` целевой таблицы |
| `foreign_key_type_mismatch` | связи | Тип колонки FK не совпадает с типом парной колонки цели |
| `foreign_key_duplicate` | связи | FK повторяет другой FK таблицы; путь — повторный FK |
| `unknown_generation` | смысл | `generated` не равно `identity` |
| `generated_requires_integer` | смысл | Генерация у колонки не `integer` и не `bigint` |
| `generated_nullable` | смысл | У колонки с генерацией явное `nullable: true` |
| `duplicate_generated` | смысл | Генерация задана второй колонке таблицы; путь — повторное вхождение |
| `check_empty` | смысл | Перечень `check` пуст |
| `check_duplicate_value` | смысл | Значение повторено в перечне; путь — повторное вхождение |
| `check_unsupported_type` | смысл | Перечень у типа вне `string`, `text`, `integer`, `bigint` |
| `check_value_wrong_kind` | смысл | Значение перечня не того вида для типа колонки |
| `check_value_out_of_range` | смысл | Значение перечня длиннее `length` или вне диапазона целого типа |
| `check_with_generated` | смысл | Перечень у колонки с генерацией |

## Ограничения YAML

- **Ключ слияния `<<` не поддерживается.** Он считается неизвестным полем. Якоря и ссылки
  (`&base`, `*base`) на значения работают.
- **Один документ в файле.** Разделитель `---` со вторым документом — нарушение `yaml_syntax`.
- **Логические значения YAML 1.1.** Слова `yes`, `no`, `on`, `off` YAML читает как логические.
  Колонку с именем `no` пишите в кавычках: `name: 'no'`. Для `nullable` эти слова допустимы,
  но понятнее `true` и `false`.
- **Теги** (`!custom`, `!!str`) не нужны. Значение с чужим тегом — нарушение `wrong_kind`.

## Ограничения и допущения

- **Ограничение:** пределы `length`, `precision`, `scale` и длины имён взяты у PostgreSQL —
  единственной СУБД первой поставки. При поддержке другой СУБД их придётся пересмотреть.
- **Ограничение:** смена типа колонки, её допустимости NULL и первичного ключа не поддерживается:
  модель, требующая такой смены, проходит `forge validate`, но отклоняется `forge generate`.
  Удаление таблицы или колонки поддерживается, переименование выражается удалением и добавлением.
- **Допущение:** перечень зарезервированных слов снят с PostgreSQL 17.11. Интеграционный тест
  сверяет его с сервером `lbfr-db-test` и падает при смене версии PostgreSQL.
- **Риск:** структурная ошибка таблицы скрывает её смысловые нарушения до исправления → агент
  правит модель ещё один круг, остальные таблицы при этом проверены полностью. Так же
  некорректная таблица скрывает нарушения FK, которые на неё ссылаются.
- **Ограничение:** набор уникальности по колонкам, допускающим NULL, пропускает повторные строки
  с NULL — это поведение PostgreSQL. Чтобы набор не допускал повторов, объявите его колонки
  с `nullable: false`.
- **Ограничение:** PostgreSQL не создаёт индекс под колонки FK, а формат индексов не описывает:
  поиск по колонкам FK и удаление строк цели на больших таблицах идут без индекса.
- **Ограничение:** действия `ON DELETE` и `ON UPDATE`, индексы и отложенные ограничения
  (`DEFERRABLE`) не поддерживаются: FK создаётся с действием `NO ACTION`.
- **Ограничение:** `CHECK` выражается только перечнем значений одной колонки. Выражения
  (`amount > 0`), ограничения над несколькими колонками и перечни у типов вне `string`, `text`,
  `integer` и `bigint` не поддерживаются.
- **Ограничение:** генерация значения — только `GENERATED BY DEFAULT AS IDENTITY`. Режим `ALWAYS`,
  параметры последовательности (`START WITH`, `INCREMENT BY`) и `serial` не поддерживаются.
- **Допущение:** последовательность колонки с генерацией не сдвигается после вставок seed
  с явными значениями. Таблица seed принадлежит seed целиком, вставки приложения в неё
  не предусмотрены — см. [seed-format.md](./seed-format.md).
- **Допущение:** колонка с перечнем без `nullable: false` допускает NULL — так ведёт себя `CHECK`
  в PostgreSQL.
