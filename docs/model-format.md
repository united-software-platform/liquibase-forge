## Назначение и границы

Модель данных описывает **полное целевое состояние** схемы `public`, а не изменение. Changelog
строится как добавляющая разница между принятой моделью `db/model.yaml` и моделью попытки.

Версия `1` формата покрывает первый срез ядра: таблицы, колонки, типы, первичный ключ (Primary Key,
PK) и обязательность (NOT NULL). Таблиц сколько угодно, связей между ними нет: внешние ключи
и уникальность входят в следующую поставку.

---

## Пример

```yaml
version: 1
tables:
  - name: customer
    columns:
      - name: id
        type: uuid
      - name: email
        type: string
        length: 255
        nullable: false
      - name: full_name
        type: text
      - name: created_at
        type: timestamp_tz
        nullable: false
    primary_key: [id]
  - name: invoice_line
    columns:
      - name: invoice_id
        type: bigint
      - name: line_no
        type: integer
      - name: amount
        type: decimal
        precision: 12
        scale: 2
        nullable: false
      - name: is_paid
        type: boolean
      - name: due_date
        type: date
      - name: created_at
        type: timestamp
    primary_key: [invoice_id, line_no]
```

Пример хранится также в `tests/fixtures/model/example.yaml`: тест проверяет, что блок выше
совпадает с файлом и что модель корректна.

## Структура файла

Файл — YAML-документ в UTF-8, корень — отображение. Других полей, кроме перечисленных, нет:
неизвестное поле — нарушение.

| Путь | Поле | Обязательно | Значение |
|------|------|-------------|----------|
| корень | `version` | да | Целое число `1` |
| корень | `tables` | да | Список таблиц, может быть пустым |
| `tables[N]` | `name` | да | Имя таблицы |
| `tables[N]` | `columns` | да | Список колонок, хотя бы одна |
| `tables[N]` | `primary_key` | да | Список имён колонок PK, хотя бы одно |
| `tables[N].columns[M]` | `name` | да | Имя колонки |
| `tables[N].columns[M]` | `type` | да | Тип из [перечня](#типы-колонок) |
| `tables[N].columns[M]` | `nullable` | нет | `true` или `false`, по умолчанию `true` |
| `tables[N].columns[M]` | `length` | для `string` | Целое число |
| `tables[N].columns[M]` | `precision` | для `decimal` | Целое число |
| `tables[N].columns[M]` | `scale` | для `decimal` | Целое число |

Порядок таблиц и колонок сохраняется, но для схемы смысла не несёт. Порядок колонок
в `primary_key` значим.

## Типы колонок

Типы формата не совпадают с типами СУБД. Отображение в PostgreSQL выполняют построение changelog
и сверка.

| Тип | Параметры | Допустимые значения | PostgreSQL |
|-----|-----------|---------------------|------------|
| `integer` | — | — | `integer` |
| `bigint` | — | — | `bigint` |
| `boolean` | — | — | `boolean` |
| `string` | `length` | от 1 до 10485760 | `varchar(length)` |
| `text` | — | — | `text` |
| `decimal` | `precision`, `scale` | `precision` от 1 до 1000, `scale` от 0 до `precision` | `numeric(precision, scale)` |
| `date` | — | — | `date` |
| `timestamp` | — | — | `timestamp without time zone` |
| `timestamp_tz` | — | — | `timestamp with time zone` |
| `uuid` | — | — | `uuid` |

Параметр, не относящийся к типу колонки, — нарушение: у `integer` нет `length`.

## Имена таблиц и колонок

Имена пишутся без кавычек и подчиняются общим правилам:

- шаблон `^[a-z][a-z0-9_]{0,62}$`: строчная латинская буква, затем строчные буквы, цифры и `_`;
- не зарезервированное слово PostgreSQL: `order`, `user`, `table` и другие из перечня
  `pg_get_keywords()` с категориями `R` и `T`;
- имена таблиц уникальны в модели, имена колонок — в пределах таблицы.

Дополнительные правила для таблиц и колонок:

| Объект | Правило | Причина |
|--------|---------|---------|
| Таблица | Не длиннее 60 символов | Имя PK `pk_<таблица>` должно уложиться в предел PostgreSQL 63 символа |
| Таблица | Не `databasechangelog` и не `databasechangeloglock` | Это таблицы журнала Liquibase |
| Колонка | Не `tableoid`, `xmin`, `cmin`, `xmax`, `cmax`, `ctid` | Это системные колонки PostgreSQL |

Схема БД всегда `public`, в модели она не указывается.

## Первичный ключ и NULL

- `primary_key` — непустой список имён колонок той же таблицы без повторов.
- Колонки PK всегда NOT NULL, `nullable` у них можно не указывать.
- Явное `nullable: true` у колонки PK — нарушение `primary_key_nullable`.
- Колонка вне PK без `nullable` допускает NULL.

## Проверка модели

Команда `forge validate --model <путь>` печатает один JSON-объект:

```json
{
  "model": "backlog/forge-model/20261017-153000/attempt-1/model.yaml",
  "valid": false,
  "violations": [
    {"path": "tables[0].columns[1].length", "code": "missing_type_parameter", "message": "у типа string обязателен length"}
  ]
}
```

| Код возврата | Когда |
|--------------|-------|
| `0` | Нарушений нет, `valid: true` |
| `1` | Есть нарушения, `valid: false` |
| `2` | Файл не прочитать: его нет, это каталог, нет прав, не UTF-8; ответ — объект `error` с видом `model_unreadable` |

Проверка идёт в два уровня:

1. **Структура.** Вид значений, состав полей, повторные ключи, версия формата.
1. **Смысл.** Имена, типы и параметры, уникальность имён, первичный ключ.

Команда возвращает все нарушения сразу: сначала структурные в порядке документа, затем смысловые
по таблицам в порядке документа. Внутри таблицы смысловые нарушения идут в устойчивом порядке:
повтор имени таблицы, имя таблицы, колонки, PK, повторы колонок, ссылки PK, NULL у колонок PK. Повторная проверка того
же файла даёт тот же ответ.

Нарушение одного элемента не останавливает проверку остальных, но есть три исключения:

- **Нарушение корня.** Корень не отображение, нет `version` или `tables`, версия не `1`:
  проверка останавливается на корне.
- **Структурное нарушение таблицы или её колонки.** Таблица не проверяется по смыслу, остальные
  таблицы проверяются полностью.
- **Некорректная колонка или PK.** Правила таблицы — уникальность колонок, ссылки PK, NULL
  у колонок PK — проверяются после исправления.

Путь нарушения ведёт от корня файла: `tables[0].columns[1].length`, `tables[2].primary_key[1]`.
Пустой путь означает весь документ.

## Коды нарушений

Коды — часть контракта команды, сообщения могут меняться.

| Код | Уровень | Когда |
|-----|---------|-------|
| `yaml_syntax` | структура | Файл не разбирается как YAML или содержит несколько документов; в сообщении строка и столбец |
| `duplicate_key` | структура | Ключ повторён в одном отображении |
| `missing_field` | структура | Нет обязательного поля |
| `unknown_field` | структура | Поле не входит в формат |
| `wrong_kind` | структура | Значение не того вида: строка вместо списка, логическое вместо числа, пустой файл |
| `unsupported_version` | структура | `version` не равно целому `1` |
| `invalid_identifier` | смысл | Имя не соответствует шаблону или длиннее предела |
| `reserved_identifier` | смысл | Зарезервированное слово, системная колонка или таблица журнала Liquibase |
| `duplicate_name` | смысл | Повтор имени таблицы в модели или колонки в таблице; путь — повторное вхождение |
| `empty_columns` | смысл | У таблицы нет колонок |
| `unknown_type` | смысл | Тип вне перечня |
| `missing_type_parameter` | смысл | Нет обязательного параметра типа |
| `unexpected_type_parameter` | смысл | Параметр не относится к типу |
| `type_parameter_out_of_range` | смысл | Значение параметра вне допустимого диапазона |
| `empty_primary_key` | смысл | `primary_key` пуст |
| `primary_key_unknown_column` | смысл | PK ссылается на отсутствующую колонку |
| `primary_key_duplicate_column` | смысл | Колонка повторена в PK |
| `primary_key_nullable` | смысл | У колонки PK явное `nullable: true` |

## Ограничения YAML

- **Ключ слияния `<<` не поддерживается.** Он считается неизвестным полем. Якоря и ссылки
  (`&base`, `*base`) на значения работают.
- **Один документ в файле.** Разделитель `---` со вторым документом — нарушение `yaml_syntax`.
- **Логические значения YAML 1.1.** Слова `yes`, `no`, `on`, `off` YAML читает как логические.
  Колонку с именем `no` пишите в кавычках: `name: 'no'`. Для `nullable` эти слова допустимы,
  но понятнее `true` и `false`.
- **Теги** (`!custom`, `!!str`) не нужны. Значение с чужим тегом — нарушение `wrong_kind`.

---

## Ограничения и допущения

- **Ограничение:** пределы `length`, `precision`, `scale` и длины имён взяты у PostgreSQL —
  единственной СУБД первой поставки. При поддержке другой СУБД их придётся пересмотреть.
- **Ограничение:** только добавляющие изменения. Модель, требующая удалить или переименовать
  таблицу или колонку, проходит `forge validate`, но отклоняется `forge generate`.
- **Допущение:** перечень зарезервированных слов снят с PostgreSQL 17.11. Интеграционный тест
  сверяет его с сервером `lbfr-db-test` и падает при смене версии PostgreSQL.
- **Риск:** структурная ошибка таблицы скрывает её смысловые нарушения до исправления → агент
  правит модель ещё один круг, остальные таблицы при этом проверены полностью.
