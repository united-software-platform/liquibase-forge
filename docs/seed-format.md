# Формат seed

`forge validate-seed` по модели данных и коды нарушений. Понятия seed определены
в [domain.md](./domain.md), формат модели — в [model-format.md](./model-format.md).

## Назначение и границы

Seed описывает **полное целевое состояние строк** справочных таблиц, а не изменение:

- таблица, указанная в seed, принадлежит ему целиком — строка БД вне seed в такой таблице лишняя;
- таблицы модели, не указанные в seed, seed не касаются;
- строка идентифицируется полным первичным ключом (Primary Key, PK) своей таблицы;
- каждое значение записано явно и по типу колонки модели: умолчаний, генерации ключей
  и вычисляемых колонок нет.

Seed проверяется по модели данных, а не сам по себе: таблицы, колонки, типы, PK, наборы `unique`
и внешние ключи (Foreign Key, FK) берутся из модели. Построение changelog данных, накат, откат
и сверка строк в этот документ не входят.

## Пример

Модель, по которой проверяется пример:

```yaml
version: 1
tables:
  - name: status_group
    columns:
      - name: code
        type: string
        length: 16
      - name: title
        type: text
        nullable: false
    primary_key: [code]
  - name: order_status
    columns:
      - name: code
        type: string
        length: 32
      - name: group_code
        type: string
        length: 16
        nullable: false
      - name: title
        type: text
        nullable: false
      - name: sort_order
        type: integer
        nullable: false
      - name: is_final
        type: boolean
        nullable: false
      - name: fee
        type: decimal
        precision: 12
        scale: 2
      - name: valid_from
        type: timestamp_tz
      - name: starts_on
        type: date
      - name: external_id
        type: uuid
      - name: description
        type: text
    primary_key: [code]
    unique:
      - [title]
    foreign_keys:
      - columns: [group_code]
        references: {table: status_group, columns: [code]}
  - name: category
    columns:
      - name: code
        type: string
        length: 32
      - name: parent_code
        type: string
        length: 32
      - name: title
        type: text
        nullable: false
    primary_key: [code]
    foreign_keys:
      - columns: [parent_code]
        references: {table: category, columns: [code]}
```

Seed по этой модели:

```yaml
version: 1
tables:
  - name: status_group
    rows:
      - {code: active, title: Активные}
      - {code: closed, title: Закрытые}
  - name: order_status
    rows:
      - code: draft
        group_code: active
        title: Черновик
        sort_order: 10
        is_final: false
      - code: paid
        group_code: active
        title: Оплачен
        sort_order: 20
        is_final: false
        fee: "12.50"
        valid_from: "2026-01-01T00:00:00+03:00"
      - code: cancelled
        group_code: closed
        title: Отменён
        sort_order: 90
        is_final: true
        starts_on: 2026-02-28
        external_id: "3f2504e0-4f89-41d3-9a0c-0305e82c3301"
        description: null
  - name: category
    rows:
      - {code: root, parent_code: root, title: Все товары}
      - {code: shoes, parent_code: root, title: Обувь}
```

Пример хранится также в `tests/fixtures/seed/example.yaml`, модель — в
`tests/fixtures/seed/model.yaml`: тест проверяет, что блоки выше совпадают с файлами и что
seed корректен по модели.

## Структура файла

Файл — YAML-документ в UTF-8, корень — отображение. Других полей, кроме перечисленных, нет:
неизвестное поле — нарушение.

| Путь | Поле | Обязательно | Значение |
|------|------|-------------|----------|
| корень | `version` | да | Целое число `1` |
| корень | `tables` | да | Список таблиц, может быть пустым |
| `tables[N]` | `name` | да | Имя таблицы модели; таблица указывается не больше одного раза |
| `tables[N]` | `rows` | да | Список строк, может быть пустым |
| `tables[N].rows[M]` | имя колонки | нет | Значение колонки по её [типу](#значения-по-типам) |

Строка — отображение «имя колонки → значение». Колонка без ключа в строке — NULL, `null` —
явный NULL. Порядок таблиц, строк и колонок в строке сохраняется и задаёт порядок нарушений,
но содержимого таблиц не меняет.

Таблица с `rows: []` принадлежит seed без строк: её целевое состояние — пустая таблица.

## Значения по типам

Разборщик не приводит значение к типу: вид значения YAML — строка, число, логическое значение —
должен совпадать с ожидаемым типом колонки. Неявного приведения нет.

| Тип колонки | Как записывается | Нормализованная форма |
|-------------|------------------|-----------------------|
| `integer` | Целое число YAML от −2147483648 до 2147483647 | Целое |
| `bigint` | Целое число YAML от −9223372036854775808 до 9223372036854775807 | Целое |
| `boolean` | Логическое значение YAML: `true`, `false` | `true` / `false` |
| `string` | Строка YAML не длиннее `length` символов | Строка как есть |
| `text` | Строка YAML | Строка как есть |
| `decimal` | Строка десятичной записи вида `"-12.50"` или целое число YAML; целая часть до `precision − scale` цифр, дробная до `scale` | Без лишних нулей дроби и без `+`: `"12.50"` → `12.5` |
| `date` | `YYYY-MM-DD` — существующая дата | `YYYY-MM-DD` |
| `timestamp` | `YYYY-MM-DDTHH:MM:SS` с дробью до шести знаков, без смещения | Без хвостовых нулей дроби |
| `timestamp_tz` | Тот же вид с обязательным смещением `Z` или `±HH:MM` | Момент в UTC с суффиксом `Z` |
| `uuid` | Строка из 32 шестнадцатеричных цифр в нижнем регистре по схеме 8-4-4-4-12 | Строка как есть |

Значения сравниваются только по нормализованной форме: `"1.50"` и `"1.5"` колонки `decimal` —
одно значение, `2026-01-01T03:00:00+03:00` и `2026-01-01T00:00:00Z` колонки `timestamp_tz` —
один момент. По этой форме проверяются повторы ключей и ссылки FK.

Неверные записи:

- `sort_order: "10"` в колонке `integer` и `code: 404` в колонке `string` — `invalid_value`:
  число и строка не взаимозаменяемы, строку с числом берите в кавычки;
- `fee: 12.5` в колонке `decimal` — `invalid_value`: дробное число YAML теряет точность,
  десятичное значение пишется строкой `"12.5"`;
- `sort_order: 3000000000` в колонке `integer`, `code: cancelled_by_user` в колонке
  `string(8)`, `fee: "1.255"` при `scale: 2` — `value_out_of_range`.

Дату без кавычек (`starts_on: 2026-02-28`) YAML помечает как дату, разборщик читает её исходный
текст: колонки `date`, `timestamp` и `timestamp_tz` принимают и такую запись, и строку в кавычках.

## NULL и ключи

- Колонка с итоговой допустимостью NOT NULL, включая каждую колонку PK, требует значения в каждой
  строке. Пропуск ключа и явный `null` — одно нарушение `null_value`.
- Колонка с генерацией значения (`generated: identity`) в seed — обычная колонка NOT NULL:
  значение задаётся явно, на выдачу значения БД seed не полагается.
- Значение колонки с перечнем `check` входит в перечень: иначе — `check_violated`. NULL в колонке,
  допускающей NULL, перечню не подчинён. Перечень проверяется только у значения, прошедшего
  проверку типа: строка `"1"` в колонке `integer` — `invalid_value`, а не `check_violated`.
- Значения PK не повторяются в строках одной таблицы: повтор — `duplicate_primary_key`
  на повторной строке.
- Значения колонок каждого набора `unique` не повторяются: повтор — `duplicate_unique`
  на повторной строке. Строка, где хотя бы одна колонка набора — NULL, в проверке набора
  не участвует, как в PostgreSQL.
- Строка, у которой нарушено хотя бы одно значение, в проверках ключей и ссылок не участвует:
  о её значении уже сообщено, а повтор по неверному значению был бы ложным.

## Ссылки и циклы

- **Цель FK — таблица seed.** Если у таблицы seed есть FK, его целевая таблица тоже указана
  в seed: справочник не ссылается на пользовательские данные. Нарушение
  `unseeded_reference_table` сообщается один раз на FK, на имени таблицы.
- **Ссылка ведёт на строку seed.** Значения колонок FK строки совпадают со значениями колонок
  цели в одной из строк целевой таблицы seed; иначе — `unresolved_reference` на строке.
  Строка, где хотя бы одна колонка FK — NULL, по этому FK не проверяется, как в PostgreSQL.
- **Цикла нет.** Ссылки между строками не образуют цикла длиннее одной строки: такой seed
  не вставить по строкам при ограничениях без отложенной проверки. Нарушение `reference_cycle`
  ставится на первую в порядке документа строку цикла, сообщение перечисляет строки цикла
  по их PK в порядке обхода: `category[code=a] → category[code=b] → category[code=a]`.
- **Ссылка строки на себя — не цикл.** Корневая строка иерархии может ссылаться на собственный
  PK, как `root` в примере: такую строку можно вставить одной командой.

## Проверка seed

Команда `forge validate-seed --seed <путь> [--model <путь>]` проверяет seed по модели и печатает
один JSON-объект:

```json
{
  "seed": "db/seed.yaml",
  "model": "db/model.yaml",
  "valid": false,
  "violations": [
    {"path": "tables[0].rows[1].sort_order", "code": "invalid_value", "message": "колонка типа integer ожидает: целое число YAML без кавычек; получено: строка '10'"}
  ]
}
```

Без `--model` seed проверяется по `model.yaml` корня принятого состояния (`FORGE_ACCEPTED_DIR`,
по умолчанию `db`). Если файла нет, модель пуста, и каждая таблица seed даёт `unknown_table`.
Поле `model` ответа называет путь модели, по которой шла проверка.

| Код возврата | Когда |
|--------------|-------|
| `0` | Нарушений нет, `valid: true` |
| `1` | Есть нарушения, `valid: false` |
| `2` | Ошибка входа; ответ — объект `error` с видом `seed_unreadable` (файл seed не прочитать), `model_unreadable` (файл модели не прочитать), `model_invalid` (модель нарушает формат, seed не проверяется) или `accepted_root_invalid` (`FORGE_ACCEPTED_DIR` задан неверно) |

При `model_invalid` нарушения модели не перечисляются: модель чинят по ответу
`forge validate --model <путь>`.

Проверка идёт в три прохода:

1. **Структура.** Корень, поля таблиц, вид `rows` и строк, повторные ключи, версия формата.
   Таблица со структурным нарушением дальше не проверяется.
1. **Таблицы и строки** в порядке документа: имя таблицы и её повтор; для каждой строки —
   колонки в порядке строки, затем пропущенные NOT NULL колонки в порядке модели; повторы PK,
   затем повторы наборов `unique`.
1. **Ссылки.** По таблицам и FK в порядке документа: сначала `unseeded_reference_table`, затем
   `unresolved_reference` по строкам; затем циклы.

Команда возвращает все нарушения сразу, в этом порядке. Повторная проверка того же seed по той же
модели даёт тот же ответ побайтово.

Нарушение одного элемента не останавливает проверку остальных, но есть исключения:

- **Нарушение корня.** Корень не отображение, нет `version` или `tables`, версия не `1`:
  таблицы не проверяются.
- **Таблицы нет в модели или она повторена.** Строки такой таблицы не проверяются.
- **Таблица со структурным нарушением.** Её строки не проверяются, а FK на неё не считается
  ссылкой вне seed: ссылки на её строки проверяются после исправления.

Путь нарушения ведёт от корня файла: `tables[0].rows[1].code`, `tables[2].name`. Пустой путь
означает весь документ.

## Коды нарушений

Коды — часть контракта команды, сообщения могут меняться.

| Код | Проход | Когда |
|-----|--------|-------|
| `yaml_syntax` | структура | Файл не разбирается как YAML или содержит несколько документов; в сообщении строка и столбец |
| `duplicate_key` | структура | Ключ повторён в одном отображении, в том числе колонка в строке |
| `missing_field` | структура | Нет обязательного поля |
| `unknown_field` | структура | Поле не входит в формат |
| `wrong_kind` | структура | Значение не того вида: таблицы не списком, строка не отображением, пустой файл |
| `unsupported_version` | структура | `version` не равно целому `1` |
| `unknown_table` | таблицы и строки | Таблицы нет в модели |
| `duplicate_table` | таблицы и строки | Таблица уже указана в seed; путь — повторное вхождение |
| `unknown_column` | таблицы и строки | У таблицы нет колонки с именем ключа строки |
| `invalid_value` | таблицы и строки | Значение не того вида или не той записи для типа колонки |
| `value_out_of_range` | таблицы и строки | Значение вне диапазона типа, длиннее `length`, больше цифр, чем у `decimal` |
| `null_value` | таблицы и строки | NULL в колонке NOT NULL или PK: ключ пропущен или указан `null` |
| `check_violated` | таблицы и строки | Значение колонки не входит в её перечень `check` |
| `duplicate_primary_key` | таблицы и строки | Значения PK повторяют другую строку таблицы; путь — повторная строка |
| `duplicate_unique` | таблицы и строки | Значения набора `unique` повторяют другую строку; путь — повторная строка |
| `unseeded_reference_table` | ссылки | Целевой таблицы FK нет в seed |
| `unresolved_reference` | ссылки | В целевой таблице seed нет строки со значениями колонок FK |
| `reference_cycle` | ссылки | Строки ссылаются друг на друга по кругу |

## Ограничения и допущения

- **Допущение:** seed проверяется по принятой модели. Согласование принятого seed с моделью,
  которую меняет операция модели, выполняет операция seed, а не эта проверка.
- **Ограничение:** умолчаний, генерации значений и вычисляемых колонок нет: каждый `uuid`, каждый
  ключ и каждое значение NOT NULL колонки записаны в seed литералом.
- **Ограничение:** колонка без ключа в строке означает NULL. Опечатка в имени колонки даёт
  `unknown_column`, а если колонка NOT NULL — ещё и `null_value`; у колонки, допускающей NULL,
  опечатку выдаёт только `unknown_column`.
- **Ограничение:** нормализация `timestamp_tz` приводит момент к UTC, исходное смещение
  не сохраняется. Для PostgreSQL это не потеря: `timestamptz` хранит момент без смещения.
- **Ограничение:** цикл ссылок между строками не поддерживается: ограничения FK создаются
  без отложенной проверки (`DEFERRABLE`), и такие строки не вставить по одной.
- **Ограничение YAML:** логические значения читаются по YAML 1.1 — `yes`, `no`, `on`, `off`
  в строковой колонке дают `invalid_value`, их берут в кавычки. Ключ слияния `<<`
  не поддерживается: в корне и в таблице это `unknown_field`, в строке — `wrong_kind`. Второй
  документ в файле — `yaml_syntax`, значение с чужим тегом — `invalid_value`. Якоря и ссылки
  (`&base`, `*base`) на значения работают, как в [формате модели](./model-format.md#ограничения-yaml).
- **Риск:** структурная ошибка таблицы скрывает нарушения её строк до исправления → агент правит
  seed ещё один круг, остальные таблицы при этом проверены полностью.
