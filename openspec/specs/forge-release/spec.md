# forge-release Specification

## Purpose

Выпуск версии Liquibase Forge: где хранится номер версии, как его повышает ручной релизный
сценарий и как номер, тег и GitHub Release остаются согласованными.

## Requirements

### Requirement: Номер версии хранится в одном файле
Номер версии forge MUST храниться только в файле `VERSION` в корне репозитория, одной строкой
вида `МАЖОР.МИНОР.ПАТЧ`. Сборка CLI SHALL брать версию пакета из `VERSION`. Ни `pyproject.toml`,
ни `uv.lock` MUST NOT содержать номер версии проекта.

#### Scenario: Версия пакета из VERSION
- **WHEN** в `VERSION` записано `0.2.0`, и CLI собран из репозитория
- **THEN** метаданные установленного пакета `liquibase-forge` называют версию `0.2.0`

#### Scenario: Смена номера не трогает lock-файл
- **WHEN** номер в `VERSION` изменён, а остальные файлы нет
- **THEN** `uv lock --check` проходит, и запуск CLI с `--frozen` не требует обновления `uv.lock`

### Requirement: Релиз запускается вручную с выбором разряда
Релизный сценарий MUST запускаться только вручную. Его единственный ввод SHALL быть разрядом
версии: `patch`, `minor` или `major`. Сценарий MUST NOT запускаться событиями репозитория:
push, тегом или слиянием.

#### Scenario: Повышение разряда
- **WHEN** сценарий запущен с разрядом `minor`, а в `VERSION` записано `0.1.0`
- **THEN** новый номер — `0.2.0`

#### Scenario: Повышение старшего разряда обнуляет младшие
- **WHEN** сценарий запущен с разрядом `major`, а в `VERSION` записано `1.4.3`
- **THEN** новый номер — `2.0.0`

### Requirement: Неразборчивый номер останавливает релиз
Если первая строка `VERSION` не имеет вида `МАЖОР.МИНОР.ПАТЧ`, сценарий MUST завершиться ошибкой
до любой записи. Сообщение SHALL называть прочитанное значение. Неполный номер MUST NOT
додумываться.

#### Scenario: Неполный номер
- **WHEN** в `VERSION` записано `0.2`
- **THEN** сценарий завершается ошибкой, называет `0.2`, и коммит, тег и релиз не создаются

### Requirement: Релиз фиксируется машинным коммитом и тегом
Сценарий MUST записать новый номер в `VERSION` и создать коммит, который меняет только этот файл.
Заголовок коммита — `Релиз vX.Y.Z`, тело называет прежний и новый номера (GIT-021). Сценарий MUST
поставить на этот коммит аннотированный тег `vX.Y.Z` и опубликовать коммит в `main` вместе с тегом.

#### Scenario: Состав релизного коммита
- **WHEN** сценарий выпустил `0.2.0` из `0.1.0`
- **THEN** в `main` есть коммит `Релиз v0.2.0`, он меняет только `VERSION`, его тело называет `0.1.0` и `0.2.0`, а тег `v0.2.0` указывает на него

### Requirement: Релиз публикуется на GitHub
После публикации тега сценарий MUST опубликовать GitHub Release `vX.Y.Z` по этому тегу. После
выпуска последний опубликованный релиз репозитория SHALL указывать на новую версию.

#### Scenario: Последний релиз
- **WHEN** сценарий выпустил `0.2.0`
- **THEN** `releases/latest` репозитория указывает на тег `v0.2.0`, и установщик forge без `--ref` ставит эту версию

### Requirement: Бейдж версии читает носитель номера
Бейдж версии в `README.md` MUST читать номер из файла `VERSION` ветки `main`. Номер MUST NOT
вписываться в URL бейджа вручную.

#### Scenario: Бейдж после релиза
- **WHEN** сценарий выпустил `0.2.0`
- **THEN** бейдж версии в `README.md` показывает `v0.2.0` без правки `README.md`
