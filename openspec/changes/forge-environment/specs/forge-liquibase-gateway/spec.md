# Spec Delta

## Purpose

Исполнение команд Liquibase в отдельном контейнере по файлу запроса через раннер на хосте: агент,
не имеющий ни Liquibase, ни Docker, получает накат и откат changelog с проверяемым результатом.

## ADDED Requirements

### Requirement: Команда передаётся файлом запроса
Шлюз MUST принимать параметры только из файла `.forge/liquibase-request.json`: идентификатор
запроса, действие `update` либо `rollback`, относительный путь changelog от корня проекта, хост,
порт и имя целевой БД, а для `rollback` — число откатываемых changeset. Учётные данные БД в файле
запроса SHALL NOT передаваться: шлюз берёт их из окружения хоста.

#### Scenario: Корректный запрос наката
- **WHEN** в файле запроса действие `update`, существующий changelog внутри проекта и БД из перечня тестовых
- **THEN** шлюз выполняет накат этого changelog на указанную БД

#### Scenario: Файл запроса отсутствует или не разбирается
- **WHEN** файла запроса нет либо он не является JSON-объектом требуемого состава
- **THEN** Liquibase не запускается, а результат содержит код исхода `2` и причину отказа

### Requirement: Changelog берётся только из проекта
Путь changelog MUST быть относительным, разрешаться внутри корня проекта и указывать
на существующий файл. Иначе шлюз SHALL отказать с кодом `2`, не запуская Liquibase. Контейнер
Liquibase MUST получать проект только на чтение.

#### Scenario: Путь выходит за корень проекта
- **WHEN** путь changelog абсолютный либо содержит переход `..` за пределы корня проекта
- **THEN** Liquibase не запускается, результат содержит код `2` и указание на недопустимый путь

#### Scenario: Liquibase не может изменить проект
- **WHEN** Liquibase исполняет накат
- **THEN** файлы проекта остаются неизменными, кроме файла результата, который пишет сам шлюз

### Requirement: Целевая БД входит в перечень тестовых
Шлюз MUST сверять хост, порт и имя БД из запроса с перечнем `FORGE_TEST_DB_ALLOWLIST` — записями
`хост:порт/имя` через запятую, где `*` на месте имени разрешает любую БД этого сервера. БД вне
перечня и пустой перечень SHALL давать отказ с кодом `2` без запуска Liquibase.

#### Scenario: БД вне перечня
- **WHEN** запрос называет БД, не совпадающую ни с одной записью перечня
- **THEN** Liquibase не запускается, результат содержит код `2` и указание на БД вне перечня

#### Scenario: Пустой перечень
- **WHEN** `FORGE_TEST_DB_ALLOWLIST` не задан либо пуст
- **THEN** любой запрос отклоняется с кодом `2`: БД не считается тестовой по умолчанию

#### Scenario: Подстановка имени БД
- **WHEN** перечень содержит `lbfr-db-test:5432/*`, а запрос называет БД `t_0001` на `lbfr-db-test:5432`
- **THEN** проверка перечня пройдена

### Requirement: Откат задаётся числом changeset
Действие `rollback` MUST откатывать ровно заданное число последних применённых changeset по
changelog запроса. Число SHALL быть целым положительным; иначе шлюз отказывает с кодом `2`.

#### Scenario: Откат двух changeset
- **WHEN** запрос `rollback` с числом `2` и changelog последней попытки
- **THEN** Liquibase откатывает два последних применённых changeset

#### Scenario: Число не задано
- **WHEN** запрос `rollback` не содержит числа либо оно не больше нуля
- **THEN** Liquibase не запускается, результат содержит код `2`

### Requirement: Результат пишется файлом при любом исходе
Перед исполнением шлюз MUST удалять прежний `.forge/liquibase-result.json`, а после — писать
новый: идентификатор запроса, действие, код исхода, вывод и диагностику Liquibase. Код исхода
SHALL быть `0` при успехе Liquibase, `1` при его ошибке, `2` при отказе шлюза.

#### Scenario: Ошибка Liquibase
- **WHEN** Liquibase завершается ошибкой наката
- **THEN** результат содержит код `1`, идентификатор запроса и диагностику Liquibase

#### Scenario: Устаревший результат не читается как новый
- **WHEN** шлюз отказал до запуска Liquibase
- **THEN** файл результата содержит идентификатор текущего запроса, а не предыдущего

### Requirement: Шлюз доступен агенту только через раннер
Шлюз MUST вызываться целями `liquibase-update` и `liquibase-rollback`, входящими в белый список
раннера. Действие цели SHALL совпадать с действием в файле запроса, иначе отказ с кодом `2`.

#### Scenario: Вызов из контейнера агента
- **WHEN** агент записывает запрос `update` и вызывает раннер с целью `liquibase-update`
- **THEN** раннер исполняет цель на хосте, а агент читает результат из файла результата

#### Scenario: Действие цели и запроса расходятся
- **WHEN** вызвана цель `liquibase-rollback`, а в запросе действие `update`
- **THEN** Liquibase не запускается, результат содержит код `2`
