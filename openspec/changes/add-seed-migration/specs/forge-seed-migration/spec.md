# Spec Delta

## Purpose

Построение changelog данных Liquibase Forge командой `forge generate-seed`: разница принятого seed
и seed попытки превращается в changeset вставки, изменения и удаления строк с явным откатом,
исполнимые на БД с ограничениями модели.

## ADDED Requirements

### Requirement: Changelog данных строится из разницы seed
`forge generate-seed` MUST строить changelog как разницу принятого seed и seed попытки
по первичному ключу. Строка только в seed попытки SHALL давать вставку, строка с тем же PK
и другими значениями — изменение, строка только в принятом seed — удаление. Значения
сравниваются в нормализованной форме формата seed.

#### Scenario: Новая строка
- **WHEN** в seed попытки у таблицы `order_status` есть строка `code: paid`, которой нет в принятом seed
- **THEN** changelog содержит вставку строки `paid` в `order_status`

#### Scenario: Изменённое значение
- **WHEN** строка `code: draft` в принятом seed имеет `title: Черновик`, а в seed попытки — `title: Набросок`
- **THEN** changelog содержит изменение `title` строки `draft` по условию на PK

#### Scenario: Одно значение в разной записи
- **WHEN** в принятом seed `fee: "1.50"`, а в seed попытки `fee: "1.5"`
- **THEN** изменения строки нет

#### Scenario: Совпадающие seed
- **WHEN** seed попытки совпадает с принятым по нормализованным значениям
- **THEN** changelog не содержит changeset: `databaseChangeLog: []`

### Requirement: Таблица, убранная из seed, очищается
Если таблица есть в принятом seed и отсутствует в seed попытки, changelog MUST удалить все её
строки из принятого seed. После этого таблица SHALL NOT принадлежать seed.

#### Scenario: Справочник убран из seed
- **WHEN** принятый seed содержит таблицу `legacy_status` с двумя строками, а seed попытки её не содержит
- **THEN** changelog удаляет обе строки `legacy_status`

### Requirement: Источники seed и модели по умолчанию
Без `--accepted-seed` принятым seed SHALL служить `seed.yaml` корня принятого состояния; нет
файла — принятый seed пуст. Без `--model` моделью SHALL служить `model.yaml` корня принятого
состояния. Оба seed MUST проходить `forge validate-seed` по этой модели до построения changelog.

#### Scenario: Первое наполнение
- **WHEN** в корне принятого состояния нет `seed.yaml`
- **THEN** changelog вставляет все строки seed попытки

#### Scenario: Seed попытки нарушает формат
- **WHEN** seed попытки содержит строку без значения PK
- **THEN** команда возвращает `1` с `changelog: null` и нарушениями как у `forge validate-seed`, прежний файл `--out` удалён

#### Scenario: Принятый seed некорректен
- **WHEN** `seed.yaml` корня принятого состояния не проходит проверку по принятой модели
- **THEN** команда возвращает `2` с видом ошибки `accepted_seed_invalid`

### Requirement: Вставки и изменения идут до удалений
Changeset MUST идти в порядке: вставки, затем изменения, затем удаления. Вставки SHALL идти
от целевых строк FK к зависимым, удаления — от зависимых к целевым. Так каждая ссылка
в промежуточном состоянии указывает на существующую строку.

#### Scenario: Перевод ссылок перед выводом строки
- **WHEN** seed попытки удаляет строку статуса `archived`, вставляет строку `closed` и меняет у строки перехода ссылку с `archived` на `closed`
- **THEN** changelog вставляет `closed`, затем меняет ссылку, затем удаляет `archived`

#### Scenario: Ссылки внутри одной таблицы
- **WHEN** в seed попытки новые строки `category` образуют дерево через `parent_code`
- **THEN** родительская строка вставляется раньше дочерней, удаление идёт в обратном порядке

### Requirement: Строки группируются в changeset по таблице и виду
Строки MUST упорядочиваться по правилу порядка с разрешением равенств по порядку таблиц и строк
в seed. Соседние в этом порядке строки одной таблицы и одного вида SHALL собираться в один
changeset. Повторная генерация с теми же аргументами MUST давать побайтово тот же файл.

#### Scenario: Справочник без ссылок
- **WHEN** seed попытки добавляет пять строк в таблицу без FK
- **THEN** changelog содержит один changeset с пятью вставками

#### Scenario: Повторная генерация
- **WHEN** `forge generate-seed` дважды вызван с теми же аргументами
- **THEN** оба файла `--out` совпадают побайтово

### Requirement: Changeset данных несёт явный откат
Каждый changeset данных MUST содержать блок `rollback`. Для вставки — удаление вставленных строк
по PK, для изменения — изменение к значениям принятого seed, для удаления — вставка строк
с значениями принятого seed. Действия отката SHALL идти в обратном порядке.

#### Scenario: Откат удаления возвращает значения
- **WHEN** changeset удаляет строку `archived` с `title: Архив`
- **THEN** его `rollback` вставляет строку `archived` с `title: Архив`

#### Scenario: Откат изменения
- **WHEN** changeset меняет `title` строки `draft` с `Черновик` на `Набросок`
- **THEN** его `rollback` меняет `title` строки `draft` на `Черновик`

### Requirement: Changeset данных идентифицирован как changeset модели
Changeset данных MUST иметь `id` вида `<штамп>-<NN>`, `author: forge` и `logicalFilePath`
`db/changelog/<штамп>.yaml`, где штамп — `subject` беклога операции. Номера SHALL идти подряд
через весь changelog с `01`.

#### Scenario: Идентичность changeset
- **WHEN** беклог операции имеет `subject: "20261025-101500"`, а changelog содержит два changeset
- **THEN** их `id` — `20261025-101500-01` и `20261025-101500-02`, `logicalFilePath` — `db/changelog/20261025-101500.yaml`

### Requirement: Значения записываются типизированными литералами
Значение MUST попадать в changelog в форме, которую PostgreSQL принимает для типа колонки без
неявного приведения от текста. Значение с кавычкой SHALL записываться без нарушения синтаксиса
и без выполнения как SQL. NULL MUST записываться явным NULL.

#### Scenario: Все типы формата
- **WHEN** seed содержит строку со значениями всех десяти типов модели, а changelog накатан на тестовую БД
- **THEN** чтение строки из БД и нормализация дают значения seed

#### Scenario: Кавычка в строке
- **WHEN** значение колонки `title` — `O'Reilly`
- **THEN** накат вставляет ровно строку `O'Reilly`

### Requirement: Изменения с конфликтом уникальности отклоняются
Если при любом допустимом порядке промежуточное состояние нарушает набор `unique`, команда MUST
вернуть `1` с `changelog: null` и перечнем `unsupported`. Это случай, когда новое значение набора
у вставленной или изменённой строки совпадает с принятым значением другой строки, которая
изменяется или удаляется. Прежний файл `--out` SHALL удаляться.

#### Scenario: Обмен значениями уникальности
- **WHEN** строка `draft` меняет `title` на `Новый`, а строка `new` — с `Новый` на `Черновик`, и `[title]` — набор `unique`
- **THEN** команда возвращает `1`, `unsupported` называет обе строки и набор `[title]`

#### Scenario: Повторное использование значения удаляемой строки
- **WHEN** строка `archived` с `title: Архив` удаляется, а новая строка `closed` получает `title: Архив`
- **THEN** команда возвращает `1` с перечнем `unsupported`

### Requirement: Удаления строк в режиме auto требуют согласия операции
Ответ команды MUST перечислять удаляемые строки таблицей и PK. Если беклог операции в режиме
`auto` имеет `allow_drop: false` и changelog удаляет строки, команда MUST вернуть `2` с видом
`drop_not_allowed` и перечнем `objects`, не записывая changelog.

#### Scenario: Удаление строки без согласия
- **WHEN** беклог операции в режиме `auto` с `allow_drop: false`, а seed попытки убирает строку `archived`
- **THEN** команда возвращает `2` с видом `drop_not_allowed`, `objects` называет `order_status` и PK `archived`

#### Scenario: Удаление в interactive
- **WHEN** беклог операции в режиме `interactive`, а seed попытки убирает строку
- **THEN** changelog записан, удаление перечислено в ответе

### Requirement: Коды возврата forge generate-seed
Команда MUST возвращать `0` при записанном changelog с перечнем changeset, вида, таблицы и числа
строк. Код `1` — seed попытки нарушает формат или изменения неисполнимы. Код `2` — нет беклога
операции, файлы не прочитать, принятые модель или seed некорректны, `drop_not_allowed`.

#### Scenario: Успешное построение
- **WHEN** seed попытки корректен и изменения исполнимы
- **THEN** команда возвращает `0`, ответ называет `changelog`, `logical_file_path` и changeset с видом `insert_rows`, `update_rows` или `delete_rows`, таблицей и числом строк
