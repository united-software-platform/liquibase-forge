## MODIFIED Requirements

### Requirement: Открытая операция находится по ключу latest
`forge status --latest` MUST находить в следах `backlog/forge-model/` и `backlog/forge-seed/`
операцию со статусом `running` или `stopped`. Если открытых операций нет, ответ SHALL содержать
`operation: null` с кодом, определяемым только проверкой среды. Более одной открытой операции
в обоих следах вместе MUST давать код `2`.

#### Scenario: Открытых операций нет
- **WHEN** все операции в обоих следах закрыты либо следов нет, а среда в порядке
- **THEN** команда возвращает код `0` и `operation: null`

#### Scenario: Остановленная операция
- **WHEN** в следе есть операция со статусом `stopped`
- **THEN** ответ называет её путь и статус `stopped`

#### Scenario: Открытая операция seed
- **WHEN** в `backlog/forge-seed/` есть операция со статусом `running`, а в `backlog/forge-model/` открытых нет
- **THEN** ответ называет её путь, статус `running` и `kind: seed`

#### Scenario: Открыты операции обоих видов
- **WHEN** в `backlog/forge-model/` и в `backlog/forge-seed/` есть по открытой операции
- **THEN** команда возвращает код `2` с перечнем обеих операций

## ADDED Requirements

### Requirement: Вид операции читается из беклога
`forge status` и `forge report` MUST называть вид операции `kind`: `model` или `seed`. Беклог
без поля `kind` SHALL читаться как `kind: model`. Команды `stop`, `resume`, `close`, `abandon`
MUST принимать беклог операции любого вида и действовать по его виду.

#### Scenario: Беклог прежнего шаблона
- **WHEN** беклог `backlog/forge-model/20261017-153000/tasks.md` не содержит поля `kind`
- **THEN** `forge status` называет `kind: model`

### Requirement: Закрытие операции модели согласует принятый seed
Если подтверждённая модель удаляет колонку таблицы принятого seed, `forge close` операции модели
MUST убрать ключ этой колонки из строк `<корень>/seed.yaml` той же правкой, что принимает модель.
Других изменений принятого seed закрытие SHALL NOT делать. `seed.yaml` MUST попадать
в `commit.files`, если изменён.

#### Scenario: Удалена колонка справочника
- **WHEN** подтверждённая модель удаляет колонку `order_status.color`, а принятый seed задаёт её в строках
- **THEN** после закрытия ключа `color` нет ни в одной строке `<корень>/seed.yaml`, файл входит в файлы для коммита

#### Scenario: Seed не затронут
- **WHEN** подтверждённая модель не удаляет колонок таблиц принятого seed
- **THEN** `<корень>/seed.yaml` не изменён и в файлы для коммита не входит
