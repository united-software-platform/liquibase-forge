# Proposal

## Why

Операции `forge-model` нужна схема PostgreSQL из 23 таблиц, а два её требования формат
`model.yaml` не выражает (LBFR-031, issue #26):

- первичный ключ `id bigint`, значение которого выдаёт БД;
- ограничение колонки перечнем значений, например `source IN ('collector', 'manual')`.

Сейчас обходной путь такой: `id` выдаёт приложение, перечни проверяет приложение. Модель
записывается без этих ограничений, поэтому схема в БД слабее, чем задумано, а сверка не может
подтвердить ограничения, которых нет в модели.

## What Changes

- **Генерация значения колонки.** У колонки появляется необязательное поле `generated`
  с единственным значением `identity`. Колонка становится `GENERATED BY DEFAULT AS IDENTITY`.
  Поле допустимо только у `integer` и `bigint`, несовместимо с `nullable: true`, и в таблице
  может быть не больше одной такой колонки.
- **Перечень значений колонки.** У колонки появляется необязательное поле `check` — непустой
  список значений без повторов. Колонка получает ограничение `CHECK (<колонка> IN (…))`. Поле
  допустимо у `string`, `text`, `integer` и `bigint`, значения проверяются по типу колонки,
  вместе с `generated` поле не используется.
- **Changelog.** Identity выражается атрибутами `autoIncrement` и `generationType: BY DEFAULT`
  в `createTable`, `addColumn` и откатах удаления. CHECK выражается отдельным changeset
  `sql` с явным откатом и именем `ck_<таблица>_<hash8>`, вычисленным из содержимого.
- **Эволюция модели.** Перечень можно добавить, убрать или изменить: это удаление и добавление
  ограничения. Включение и выключение `generated` у существующей колонки отклоняется новым
  неподдерживаемым изменением `column_generated_changed`. Новая колонка с `generated`
  в существующей таблице разрешена.
- **Сверка.** Identity сверяется по `pg_attribute.attidentity` (`column_generated_mismatch`).
  CHECK разбирается из определения ограничения в колонку и множество значений и сверяется
  по содержимому (`check_missing`, `check_unexpected`). Проверка отката получает виды
  `check_absent` и `check_present`.
- **Seed.** `forge validate-seed` отклоняет значение вне перечня (`check_violated`), а
  `forge generate` отклоняет новый или суженный перечень, которому не отвечают строки
  принятого seed (`check_violated_by_seed`).
- **Документация.** Описание формата, changelog, сверки и предметной области дополняется,
  а ограничение «CHECK не поддерживается» заменяется ограничением «CHECK только перечнем».
- Версия формата не меняется (`version: 1`): новые поля необязательны, и прежние модели
  остаются корректными без правок. Изменение выходит в выпуске `0.5.0`.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `forge-data-model`: колонка получает необязательные поля `generated` и `check` с правилами
  их проверки и кодами нарушений.
- `forge-migration`: changelog выражает identity и CHECK, ограничение CHECK отождествляется
  по содержимому и именуется `ck_<таблица>_<hash8>`, смена `generated` отклоняется, возврат CHECK
  после отката проверяется, новый перечень проверяется против принятого seed.
- `forge-reconciliation`: сверка identity колонки и CHECK-ограничений по содержимому.
- `forge-seed-data`: значение колонки с перечнем проверяется по перечню, а колонка с генерацией
  значения требует в seed явного значения.

## Impact

- **Код модели:** `src/forge/modeling/`. Сюда входят читатель YAML, черновик, `Column`, фабрика
  и инварианты таблицы.
- **Код changelog:** `src/forge/migration/`. Сюда входят `ModelDiff`, изменения схемы, запись
  и сводка changelog, имена ограничений, проверка ограничений при откате, конфликты seed.
- **Код сверки:** `src/forge/reconciliation/`. Сюда входят интроспекция `pg_catalog`,
  фактическая схема и сравнение.
- **Код seed:** `src/forge/seeding/` — проверка значений по перечню.
- **Документация:** `docs/model-format.md`, `docs/migration.md`, `docs/reconciliation.md`,
  `docs/domain.md`, `docs/seed-format.md`, `docs/operation.md`, `README.md`.
- **Тесты:** модульные и интеграционные на PostgreSQL 17 и Liquibase из образа kit'а.
- **Совместимость:** принятые модели, changelog и seed прежних версий остаются корректными;
  ответы команд получают только новые значения видов и кодов.
- **Выпуск:** `0.5.0` (разряд `minor`), milestone `v0.5.0`.
