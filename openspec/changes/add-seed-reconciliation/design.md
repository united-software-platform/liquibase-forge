# Design

## Context

Мотивация — в `proposal.md`, требования — в `specs/forge-seed-reconciliation/spec.md`. Формат
и нормализация значений — изменение `add-seed-format`, changelog данных — `add-seed-migration`.

Что есть сейчас в контексте «Сверка» (`src/forge/reconciliation/`):

- **Сценарий.** `ReconcileUseCase` проверяет перечень тестовых, загружает модель, читает
  changeset changelog (`ChangesetListReaderInterface`), каталог PostgreSQL
  (`SchemaIntrospectorInterface`) и журнал (`JournalRecordsReaderInterface`). Затем складывает
  `SchemaComparison` и `JournalCheck` и пишет `reconcile.json`.
- **Расхождение.** `Discrepancy` — `kind`, `table`, `column`, `changeset`, `expected`, `actual`,
  `message`.
- **Чтение changelog.** `ChangesetListReader` читает только `id`, `author` и `logicalFilePath`
  changeset, поэтому подходит и для changelog данных без правок.

## Goals / Non-Goals

**Goals:**

- Вердикт попытки seed с расхождениями, по которым LLM правит seed следующей попытки.
- Сравнение того же нормализованного представления, что строит и проверяет seed.

**Non-Goals:**

- Сверка структуры после наката seed: seed её не меняет. Расхождение структуры с моделью
  обнаружит следующая сверка модели.
- Сверка таблиц, не принадлежащих seed.

## Decisions

### Сценарий в контексте «Наполнение», журнал — из «Сверки»

`ReconcileSeedUseCase` живёт в `src/forge/seeding/application/`: сравнение строк — понятие seed.
Проверка журнала одна для двух вердиктов, поэтому она переиспользуется. Сценарий получает
контракты `ChangesetListReaderInterface` и `JournalRecordsReaderInterface` и доменный
`JournalCheck` контекста «Сверка». Зависимость идёт в одну сторону, по прецеденту зависимости
«Сверки» от «Моделирования».

Альтернатива — режим `--seed` у `forge reconcile` — отклонена: у двух сверок разные входы,
разные виды расхождений и разные источники ожидаемого. Одна команда с ветвлением получила бы
две причины меняться (CLAR-017).

### Поле `key` у `Discrepancy`

`Discrepancy` получает необязательное поле `key` со значением по умолчанию `None`. `forge reconcile`
его не заполняет, и в ответе `reconcile` поле не появляется: формат сверки модели не меняется.
В ответе `reconcile-seed` поле `key` есть у каждого расхождения. Альтернатива — отдельный тип
расхождения строк — дала бы два понятия «расхождение» (DDD-002).

### Чтение строк и нормализация

Строки читаются запросом `SELECT <колонки модели> FROM <таблица> ORDER BY <PK>`. Имена берутся
из модели, они уже прошли правила идентификаторов. Значения `psycopg` приходят типами Python
и переводятся в нормализованную форму той же фабрикой `SeedValue`, что разбирает seed:

| Тип | Из `psycopg` |
|-----|--------------|
| `integer`, `bigint` | `int` |
| `boolean` | `bool` |
| `string`, `text` | `str` |
| `decimal` | `Decimal`, без лишних нулей дроби |
| `date` | `date.isoformat()` |
| `timestamp` | `datetime.isoformat()` без хвостовых нулей дроби |
| `timestamp_tz` | `datetime` в UTC с суффиксом `Z` |
| `uuid` | `str(UUID)` |

Одна фабрика на обе стороны — главная гарантия, что `"1.50"` и `numeric 1.5` не дадут ложного
`value_mismatch`. Интеграционный тест накатывает строку всех десяти типов и сверяет её без
расхождений.

### Ожидаемое для убранных таблиц

Принятый seed читается только ради перечня таблиц, убранных из seed попытки. Их ожидаемое
содержимое — пустое. Так сверка видит, что `delete` changelog данных действительно очистил
таблицу.

## Risks / Trade-offs

- [Большая таблица seed читается целиком] → справочники малы. Для таблиц вне seed чтения нет.
- [`timestamp` в PostgreSQL хранит микросекунды, а seed может содержать меньше знаков] →
  нормализация отбрасывает хвостовые нули с обеих сторон.
- [Таблица seed удалена из схемы между накатом и сверкой] → это нарушение допущения «схемой
  управляет только Forge». Запрос падает ошибкой БД, команда возвращает `2` с видом
  `database_unavailable` и диагностикой.

## Migration Plan

Миграции нет: команда новая. Поле `key` у `Discrepancy` необязательное, ответ `forge reconcile`
не меняется, это подтверждают его существующие тесты.
