# Spec Delta

## MODIFIED Requirements

### Requirement: Расхождения ограничений идут в устойчивом порядке
Расхождения ограничений таблицы MUST следовать за расхождением её первичного ключа: наборы
уникальности модели по порядку, лишние наборы, перечни значений модели по порядку колонок,
лишние перечни, внешние ключи модели по порядку, лишние внешние ключи; лишние ограничения —
в порядке их описания колонками.

#### Scenario: Повторная сверка
- **WHEN** сверка с расхождениями ограничений дважды выполнена на неизменной БД
- **THEN** перечни расхождений совпадают

#### Scenario: Перечень между уникальностью и внешними ключами
- **WHEN** у таблицы `event` в БД нет набора уникальности, перечня `source` и внешнего ключа модели
- **THEN** перечень содержит `unique_missing`, затем `check_missing`, затем `foreign_key_missing`

## ADDED Requirements

### Requirement: Генерация значения колонки сверяется
Для колонки, которая есть и в модели, и в БД, генерация значения MUST совпадать: колонка
с `generated: identity` SHALL быть identity `BY DEFAULT`, колонка без `generated` — не identity.
Иначе SHALL давать расхождение `column_generated_mismatch` с ожидаемым `identity` или `absent`
и фактическим `identity`, `identity_always` или `absent`. Расхождение идёт после расхождений
типа и NULL этой колонки.

#### Scenario: Генерация совпадает
- **WHEN** в модели `customer.id` имеет `generated: identity`, а в БД колонка — identity `BY DEFAULT`
- **THEN** расхождений по генерации нет

#### Scenario: Генерации нет в БД
- **WHEN** в модели `customer.id` имеет `generated: identity`, а в БД колонка не identity
- **THEN** перечень содержит `column_generated_mismatch` с ожидаемым `identity` и фактическим `absent`

#### Scenario: Генерация ALWAYS
- **WHEN** в модели `customer.id` имеет `generated: identity`, а в БД колонка — identity `ALWAYS`
- **THEN** перечень содержит `column_generated_mismatch` с фактическим `identity_always`

#### Scenario: Лишняя генерация
- **WHEN** в модели `customer.id` без `generated`, а в БД колонка — identity
- **THEN** перечень содержит `column_generated_mismatch` с ожидаемым `absent` и фактическим `identity`

### Requirement: Перечни значений сверяются по содержимому
Сверка MUST читать ограничения `CHECK` таблиц схемы `public` и сравнивать их с перечнями `check`
модели по колонке и множеству значений. Перечень модели, которого нет в БД, SHALL давать
`check_missing`; ограничение в БД, которого нет в модели, — `check_unexpected`. Имя ограничения
и порядок значений MUST NOT сравниваться.

#### Scenario: Перечень совпадает
- **WHEN** модель объявляет у `event.source` `check: [collector, manual]`, а в БД ограничение с произвольным именем допускает `manual` и `collector`
- **THEN** расхождений по перечням нет

#### Scenario: Перечня нет в БД
- **WHEN** модель объявляет перечень у `event.source`, а ограничения в БД нет
- **THEN** перечень расхождений содержит `check_missing` для `event` с колонкой `source`

#### Scenario: Другой набор значений
- **WHEN** модель объявляет у `event.source` `check: [collector, manual]`, а в БД ограничение допускает `collector`, `manual` и `import`
- **THEN** перечень содержит `check_missing` для перечня модели и `check_unexpected` для ограничения в БД

#### Scenario: Перечни целых колонок
- **WHEN** модель объявляет у `task.priority` типа `integer` `check: [1, 2, 3]`, и ограничение накатано changelog модели
- **THEN** расхождений по перечням нет

#### Scenario: Отсутствующая таблица
- **WHEN** таблицы модели `event` с перечнем в БД нет
- **THEN** перечень содержит `table_missing` для `event` и не содержит расхождений её перечней

### Requirement: Нераспознанное ограничение CHECK считается лишним
Ограничение `CHECK` в БД, которое не выражается перечнем значений одной колонки — выражение
над несколькими колонками, сравнение, вызов функции, — MUST давать расхождение `check_unexpected`
с исходным определением ограничения в фактическом значении. Такое ограничение SHALL NOT приводить
к ошибке окружения.

#### Scenario: Ограничение-выражение
- **WHEN** в таблице `invoice` БД есть ограничение `CHECK (amount > 0)`, а в модели перечней у `invoice` нет
- **THEN** перечень содержит `check_unexpected` для `invoice`, фактическое значение — определение ограничения, команда возвращает код `1`
