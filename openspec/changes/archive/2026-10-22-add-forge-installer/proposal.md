# Proposal

## Why

Liquibase Forge переносится в целевой проект вручную: владелец копирует семь путей и вписывает
отличия forge в четыре файла SDD Developer Kit, а при обновлении повторяет то же самое. Перенос
легко сделать неполным, и правки владельца в файлах kit'а теряются. Задача GitHub #2 (LBFR-016)
просит установщик, который ставит forge одной командой и повторно запускается без потерь.

## What Changes

- Новый POSIX-скрипт `install.sh` в корне репозитория forge. Он ставит forge в текущий каталог
  проекта с kit'ом из архива GitHub по `--ref` (по умолчанию — последний релизный тег `v*`) либо
  из локальной копии по `--source`. Ключи: `--ref`, `--source`, `--dry-run`, `--yes`. Коды
  возврата: `0`, `1`, `2`.
- Предусловие: в проекте есть `.sdd-kit-manifest.json` с `kit_version` не ниже `1.5.0`.
- Машинный перечень поставки `delivery.txt` в корне репозитория хранит пары `источник → цель`.
  Код CLI (`src/forge`, `pyproject.toml`, `uv.lock`) переносится в uv-подпроект `tools/forge/`
  целевого проекта и не конфликтует с его `pyproject.toml`.
- Отличия forge вносятся в `Makefile`, `.env.example`, `docker-compose.yml`,
  `tools/host-runner/runner.py` и `.gitignore` маркированными блоками
  `# >>> liquibase-forge` / `# <<< liquibase-forge`. Текст вне маркеров не меняется. Пропавший
  блок вставляется заново, а неузнаваемое место вставки даёт код `1` и печатает блок для ручной
  вставки.
- Манифест установки `.forge-manifest.json` хранит версию, ref, время и SHA-256 файлов поставки
  и блоков. Правки владельца попадают в план и перезаписываются только после подтверждения
  или с `--yes`.
- Обёртка `tools/forge-env/forge.sh` одинаково запускает CLI в репозитории forge и в целевом
  проекте. Навык `forge` и `docs/` вызывают CLI через неё вместо `uv run forge`.
- В репозитории forge отличия в четырёх файлах kit'а обрамляются теми же маркерами, а блоки
  берутся из одного источника.
- Шаг 1 `README.md` описывает установщик и коды возврата. Ограничение «Установщика нет»
  снимается.
- Вне объёма: удаление forge из проекта и механизм расширения файлов в самом kit'е. Для
  механизма расширения заводится отдельная задача в репозитории kit'а.

## Capabilities

### New Capabilities

- `forge-delivery`: установка Liquibase Forge в проект с SDD Developer Kit — предусловия,
  источник версии, перечень поставки, маркированные блоки в файлах kit'а, манифест установки,
  план и подтверждение перезаписи, коды возврата, запуск CLI в установленном проекте.

### Modified Capabilities

Нет: остальные спецификации forge не задают, как вызывается CLI и как он попадает в проект.

## Impact

- Новые файлы: `install.sh`, `delivery.txt`, `tools/forge-env/forge.sh`, фрагменты блоков
  и тесты установщика.
- Правки: `Makefile`, `.env.example`, `docker-compose.yml`, `tools/host-runner/runner.py`
  и `.gitignore` получают маркеры. Навык `.claude/skills/forge/SKILL.md` и `docs/operation.md`
  переходят на обёртку. Меняются `README.md` (шаг 1, «Ограничения») и `CONTRIBUTING.md`
  (раздел «Отличия от поставки kit'а», проверки).
- Зависимости целевого окружения: `curl` и `tar` там, где запускается установщик, и `uv`
  в контейнере агента.
- Релиз: первая устанавливаемая версия — `v0.2.0`.
