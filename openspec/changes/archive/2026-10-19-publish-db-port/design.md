# Design

## Context

- `docker/lbfr/docker-compose.yaml` подключается в `docker-compose.yml` kit'а секцией `include:`
  с `project_directory: .`: подстановки `${VAR}` берутся из `.env` корня проекта.
- `lbfr-db` сейчас без секции `ports`; комментарий файла и `docs/architecture.md` прямо
  утверждают, что порты на хост не публикуются.
- `FORGE_DB_HOST` и `FORGE_DB_PORT` — адрес БД внутри сети Compose: по нему ходят агент
  (интроспекция) и шлюз (через `FORGE_TEST_DB_ALLOWLIST`).
- `make forge-env-sync` дописывает в `.env` любые недостающие `FORGE_*` из `.env.example`.
  `make forge-env-up` выполняет `docker compose up -d --wait` и пересоздаёт контейнер при смене
  конфигурации; данные лежат в томе `lbfr-db-data` и пересоздание переживают.
- Диапазон хостовых портов проекта в документации не зафиксирован; единственный опубликованный
  порт — раннер, `AGENT_RUNNER_PORT=11900`.
- Агент работает в контейнере без Docker и без `ss`: свободен ли порт на хосте, он сам проверить
  не может.

## Goals / Non-Goals

**Goals:**

- Доступ к `lbfr-db` с хоста и из сети хоста по одному настраиваемому порту.
- Явная ошибка подготовки окружения, если порт в `.env` не задан.

**Non-Goals:**

- Публикация `lbfr-db-test`.
- Смена учётных данных по умолчанию, TLS и ограничение доступа средствами PostgreSQL
  (`pg_hba.conf`).
- Использование хостового порта агентом или шлюзом.

## Decisions

### Маппинг на все интерфейсы

`ports: - "${FORGE_DB_HOST_PORT}:5432"` — левая часть без адреса, порт слушается на всех
интерфейсах хоста. Выбор пользователя при планировании.

Альтернатива — `127.0.0.1:${FORGE_DB_HOST_PORT}:5432`: безопаснее, но закрывает подключение
с других машин; отклонена пользователем.

### Порт без значения по умолчанию в compose-файле

Подстановка — `${FORGE_DB_HOST_PORT}` без `:-…` и без `:?…`.

- `:-11932` — литерал порта в compose-файле, противоречит DOCK-009 и дублирует `.env.example`.
- `:?…` — Compose прерывает разбор всей конфигурации, включая сервис агента `claude` из файла
  kit'а: установка, не выполнившая `make forge-env-sync`, не смогла бы запустить даже сессию
  агента. Цена ошибки несоразмерна.

Пустое значение диагностирует `make forge-env-check` (см. ниже), а не Compose.

### Значение 11932 и диапазон проекта 11900–11999

Диапазон выводится из уже опубликованного порта раннера `11900` и фиксируется в `README.md`
по DOCK-008. `11932` выбран по окончанию штатного порта `5432`, чтобы порт узнавался.
Это допущение: если у пользователя закреплён другой диапазон, меняются только `.env.example`
и строка `README.md`.

### Отдельная переменная вместо `FORGE_DB_PORT`

`FORGE_DB_PORT` остаётся портом внутри сети Compose. Совмещение ролей сломало бы адрес агента
и записи `FORGE_TEST_DB_ALLOWLIST` при любом хостовом порту, кроме `5432`.

### Проверка в `tools/forge-env/check.sh`

Скрипт уже вызывает `docker compose config`. Добавляется шаг: прочитать конфигурацию `lbfr-db`
в JSON (`docker compose config --format json lbfr-db`), разобрать её `python3` (уже требуется
на хосте) и убедиться, что у порта `5432` есть непустой `published`. Иначе — сообщение
с `FORGE_DB_HOST_PORT` и `make forge-env-sync`, код `1`. При успехе печатается порт. Шаг
не зависит от того, как Compose трактует пустую левую часть маппинга: и ошибка разбора, и
отсутствие `published` дают отказ.

## Risks / Trade-offs

- [БД с учётными данными по умолчанию `forge`/`forge` доступна из сети хоста] → блок
  `> **Внимание:**` в `README.md`: сменить `FORGE_DB_PASSWORD` либо закрыть порт сетевым экраном.
- [Docker публикует порт правилами iptables в обход `ufw` и подобных экранов] → указать это
  в том же блоке, чтобы закрытие порта экраном не считалось достаточным по умолчанию.
- [Порт `11932` занят на хосте] → `make forge-env-up` падает с `port is already allocated`;
  в `README.md` — проверка `ss -ltn` и смена значения в `.env`.
- [Существующая установка без переменной в `.env`] → `make forge-env-check` даёт отказ
  с подсказкой `make forge-env-sync`; шаги миграции — ниже.

## Migration Plan

1. `make forge-env-sync` — в `.env` дописывается `FORGE_DB_HOST_PORT=11932`.
2. `make forge-env-check` — порт `lbfr-db` опубликован.
3. `make forge-env-up` — `lbfr-db` пересоздаётся с публикацией порта, данные тома сохраняются.

Сессию агента перезапускать не нужно: агент новую переменную не использует.

Откат: удалить секцию `ports` у `lbfr-db` и шаг проверки, затем `make forge-env-up`.
Переменная в `.env` после отката безвредна.
