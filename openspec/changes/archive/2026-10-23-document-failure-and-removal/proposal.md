# Proposal

## Why

При подготовке 0.2.0 (LBFR-018) из документа кейсов выпали две задачи применяющего forge. Первая — разобраться,
почему операция закрылась с `failure` после трёх попыток. Вторая — убрать forge из проекта: установщик его
не удаляет, а `README.md` в «Ограничениях» прямо отправляет делать это вручную, не объясняя как. Задача #9
(LBFR-021) входит в выпуск 0.3.0. Критерий закрытия — аудит `project-docs` по `docs/use-cases.md`
и `README.md` без расхождений.

## What Changes

- **Кейс 11 «Хочу понять, почему операция закрылась с failure».**
  - Какие поля отчёта читать: статус, число попыток, по каждой попытке — вердикт, расхождения
    из `reconcile.json`, действие и `verified` из `rollback.json`.
  - Где лежат файлы попыток: `backlog/forge-model/<штамп>/attempt-N/` — `model.yaml`, `changelog.yaml`,
    `apply.json`, `reconcile.json`, `rollback.json`.
  - Как прочитать причину: ошибка Liquibase при накате в `apply.json` или расхождения сверки по видам.
  - Что поменять в намерении для новой операции.
  - Схема после `failure` не изменилась, след операции коммитится.
- **Кейс 12 «Хочу удалить forge из проекта».**
  - Порядок удаления:
    1. остановить и удалить сервисы `lbfr-db`, `lbfr-db-test`, `lbfr-liquibase`, том данных `lbfr-db-data`
       и образ Liquibase — пока Compose ещё видит файл `docker/lbfr/docker-compose.yaml`;
    1. удалить файлы поставки по перечню `files` из `.forge-manifest.json`;
    1. убрать блоки между маркерами `# >>> liquibase-forge` / `# <<< liquibase-forge` из `Makefile`,
       `.env.example`, `docker-compose.yml`, `tools/host-runner/runner.py`, `.gitignore`;
    1. убрать переменные `FORGE_*` и `LBFR_*` из `.env`, каталог `.forge/` и сам манифест;
    1. перезапустить раннер на хосте.
  - Что оставить: принятое состояние (`db/` или `FORGE_ACCEPTED_DIR`) и след `backlog/forge-*`. Это файлы
    проекта, и принятый changelog по-прежнему накатывается без forge (кейс 10).
- **`README.md`.**
  - Шаг 4 заканчивается ссылкой на кейсы 3 и 11 (DGN-005): оба относятся к исполнению операции.
  - Пункт «Установщик не удаляет forge» в «Ограничениях» ссылается на кейс 12.
  - «Куда дальше» называет новые задачи.
- **`docs/use-cases.md`:** назначение, навигация, строка версии 1.0.3.
- Порядок удаления проверяется на стенде: установка `install.sh --source` во временный проект, удаление
  по кейсу, сравнение с состоянием до установки. Docker-часть проверяется на хосте через раннер.

Поведение forge и установщика не меняется. Команды удаления forge нет и в этом change не появляется.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

Нет. Change меняет только документы для применяющего forge: требования к операции, отчёту и установщику
остаются прежними. Поэтому change объявляет `skip_specs: true`.

## Impact

- `docs/use-cases.md` — два кейса, назначение, навигация, таблица версий.
- `README.md` — строка «Подробнее» шага 4, пункт «Ограничений», «Куда дальше».
- Код, тесты и поставка не меняются. Временные проверочные файлы стенда удаляются после проверки.
- Аудит навыком `project-docs` по `README.md` и `docs/use-cases.md` — критерий закрытия #9.
