# Spec Delta

## MODIFIED Requirements

### Requirement: Закрытие операции под стоп-знаком
Беклог операции MUST завершаться закрытием операции, перед которым в режиме `interactive`
запрашивается подтверждение владельца с показом исхода. При успехе закрытие SHALL принимать
модель и changelog в корень принятого состояния со статусом `success`; после трёх неудач —
ничего не принимать и ставить статус `failure`.

#### Scenario: Закрытие успешной операции
- **WHEN** владелец подтверждает закрытие операции с успешной сверкой
- **THEN** модель и changelog успешной попытки приняты в корень принятого состояния, статус операции `success`

#### Scenario: Закрытие после трёх неудач
- **WHEN** владелец подтверждает закрытие операции, все попытки которой неуспешны
- **THEN** в корне принятого состояния ничего не изменилось, статус операции `failure`

## ADDED Requirements

### Requirement: Шаблон попытки не называет корень принятого состояния
Беклог попытки MUST строить changelog командой `forge generate` без аргумента `--accepted`:
принятую модель находит CLI по корню принятого состояния. Путь корня SHALL NOT появляться
в тексте порождённого беклога.

#### Scenario: Порождённый беклог попытки
- **WHEN** беклог попытки порождён шаблоном `forge-apply`
- **THEN** задача построения changelog вызывает `forge generate` без `--accepted`, и литерал `db/model.yaml` в беклоге отсутствует
