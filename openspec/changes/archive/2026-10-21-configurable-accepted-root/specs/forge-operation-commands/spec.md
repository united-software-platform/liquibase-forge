# Spec Delta

## ADDED Requirements

### Requirement: Корень принятого состояния задаётся переменной окружения
Команды `forge` MUST брать корень принятого состояния из `FORGE_ACCEPTED_DIR`. Незаданная или
пустая переменная SHALL давать корень `db`. Значение MUST быть относительным путём внутри
корня проекта: абсолютный путь либо выход за корень проекта SHALL давать код `2` у команд,
обращающихся к принятому состоянию.

#### Scenario: Переменная не задана
- **WHEN** `FORGE_ACCEPTED_DIR` не задана, а попытка операции подтверждена
- **THEN** `forge close` принимает модель в `db/model.yaml`

#### Scenario: Корень вне db
- **WHEN** `FORGE_ACCEPTED_DIR=.forge/db`, а попытка операции подтверждена
- **THEN** `forge close` принимает модель в `.forge/db/model.yaml`, а каталог `db/` не появляется

#### Scenario: Абсолютный путь
- **WHEN** `FORGE_ACCEPTED_DIR=/srv/db`
- **THEN** `forge close` возвращает код `2` с указанием на `FORGE_ACCEPTED_DIR` и ничего не принимает

## MODIFIED Requirements

### Requirement: Статус проверяет тестовую среду
`forge status` MUST проверять подключение к целевой БД из `FORGE_DB_*`, вхождение БД в
`FORGE_TEST_DB_ALLOWLIST`, ответ раннера на цель `help` и корректность корня принятого
состояния из `FORGE_ACCEPTED_DIR`. Любая непройденная проверка SHALL давать код `2`, а ответ
MUST называть каждую проверку и её итог. Проверка `accepted` MUST называть итоговый путь корня.

#### Scenario: Раннер не отвечает
- **WHEN** БД доступна и входит в перечень, корень принятого состояния корректен, а раннер не отвечает
- **THEN** команда возвращает код `2`, проверка раннера отмечена непройденной, остальные — пройденными

#### Scenario: Среда в порядке
- **WHEN** все четыре проверки пройдены
- **THEN** команда возвращает код `0`

#### Scenario: Корень принятого состояния назван
- **WHEN** `FORGE_ACCEPTED_DIR=.forge/db`, а остальные проверки пройдены
- **THEN** проверка `accepted` пройдена и называет путь `.forge/db`, команда возвращает код `0`

#### Scenario: Корень вне проекта
- **WHEN** `FORGE_ACCEPTED_DIR=../db`
- **THEN** проверка `accepted` не пройдена, команда возвращает код `2`

### Requirement: Закрытие успешной операции принимает модель в db
`forge close --operation <беклог>` при подтверждённой попытке MUST скопировать её `model.yaml`
в `<корень>/model.yaml` и `changelog.yaml` в `<корень>/changelog/<штамп>.yaml`, добавить
`include` этого файла в конец `<корень>/changelog/master.yaml`, если его там нет, и поставить
статус `success`. `<корень>` — корень принятого состояния. Команда SHALL NOT коммитить.

#### Scenario: Первая успешная операция
- **WHEN** корня принятого состояния ещё нет, а попытка 2 подтверждена
- **THEN** появились `<корень>/model.yaml`, `<корень>/changelog/<штамп>.yaml` и `master.yaml` с одним `include`, статус `success`

#### Scenario: Принятый master накатывается
- **WHEN** после двух успешных операций накатывается `<корень>/changelog/master.yaml` на пустую БД
- **THEN** Liquibase применяет changeset обеих операций в порядке их принятия

### Requirement: Закрытие после трёх неудач не меняет db
При вердикте `failure` у всех трёх попыток и подтверждённом `rollback.json` каждой
`forge close` MUST ставить статус `failure`, не трогая корень принятого состояния. Если нет
ни подтверждённой попытки, ни трёх неудач с подтверждённым откатом, команда SHALL возвращать
код `1` с причиной и ничего не менять.

#### Scenario: Три неудачи
- **WHEN** все три попытки неуспешны и откат каждой подтверждён
- **THEN** статус `failure`, содержимое корня принятого состояния не изменилось

#### Scenario: Закрывать рано
- **WHEN** у операции одна неуспешная попытка
- **THEN** команда возвращает код `1`, статус остаётся `running`

#### Scenario: Повторное закрытие
- **WHEN** `forge close` вызвана для уже закрытой операции
- **THEN** код `0`, статус и корень принятого состояния не изменились

### Requirement: Отчёт содержит всё для разбора исхода
`forge report --operation <беклог>` MUST печатать статус, число использованных попыток, пути
модели и changelog, перечень беклогов, а для каждой попытки — вердикт, расхождения сверки
из `reconcile.json` и итог отката из `rollback.json`. При `success` отчёт SHALL перечислять файлы
корня принятого состояния для коммита владельцем. Код `1` MUST возвращаться только при статусе
`failure`.

#### Scenario: Отчёт об успехе
- **WHEN** операция закрыта со статусом `success` на второй попытке
- **THEN** отчёт называет две попытки, пути в корне принятого состояния, расхождения первой попытки, её откат и файлы для коммита, код `0`

#### Scenario: Отчёт о неудаче
- **WHEN** операция закрыта со статусом `failure`
- **THEN** отчёт содержит три попытки с расхождениями и откатом каждой, код `1`

#### Scenario: Отчёт при корне вне db
- **WHEN** `FORGE_ACCEPTED_DIR=.forge/db`, а операция закрыта со статусом `success`
- **THEN** файлы для коммита названы путями в `.forge/db/`
