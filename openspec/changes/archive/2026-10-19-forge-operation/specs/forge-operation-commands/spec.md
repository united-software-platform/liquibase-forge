# Spec Delta

## Purpose

Команды CLI состояния операции Liquibase Forge: статус и проверка тестовой среды, остановка
и продолжение, закрытие с принятием модели в `db/` и итоговый отчёт для LLM.

## ADDED Requirements

### Requirement: Статус операции читается из её беклога
`forge status --operation <беклог операции>` MUST печатать намерение, режим, статус операции,
вердикт, беклог и каталог каждой попытки и номер подтверждённой попытки. Подтверждённой SHALL
считаться попытка с вердиктом `success`.

#### Scenario: Операция после первой неудачи
- **WHEN** у операции `verdict.attempt_1: failure`, остальные вердикты пусты
- **THEN** ответ называет статус `running`, одну использованную попытку и отсутствие подтверждённой попытки

#### Scenario: Беклога нет
- **WHEN** путь `--operation` не ведёт к беклогу операции
- **THEN** команда возвращает код `2`

### Requirement: Статус проверяет тестовую среду
`forge status` MUST проверять подключение к целевой БД из `FORGE_DB_*`, вхождение БД в
`FORGE_TEST_DB_ALLOWLIST` и ответ раннера на цель `help`. Любая непройденная проверка SHALL
давать код `2`, а ответ MUST называть каждую проверку и её итог.

#### Scenario: Раннер не отвечает
- **WHEN** БД доступна и входит в перечень, а раннер не отвечает
- **THEN** команда возвращает код `2`, проверка раннера отмечена непройденной, остальные — пройденными

#### Scenario: Среда в порядке
- **WHEN** все три проверки пройдены
- **THEN** команда возвращает код `0`

### Requirement: Открытая операция находится по ключу latest
`forge status --latest` MUST находить в следе `backlog/forge-model/` операцию со статусом `running`
или `stopped`. Если открытых операций нет, ответ SHALL содержать `operation: null` с кодом,
определяемым только проверкой среды. Более одной открытой операции MUST давать код `2`.

#### Scenario: Открытых операций нет
- **WHEN** все операции в следе закрыты либо следа нет, а среда в порядке
- **THEN** команда возвращает код `0` и `operation: null`

#### Scenario: Остановленная операция
- **WHEN** в следе есть операция со статусом `stopped`
- **THEN** ответ называет её путь и статус `stopped`

### Requirement: Остановка и продолжение меняют только статус
`forge stop --operation <беклог> --reason <текст>` MUST переводить операцию из `running`
в `stopped` и записывать причину во фронтматтер. `forge resume --operation <беклог>` MUST
переводить `stopped` в `running`. Закрытую операцию ни одна из команд SHALL NOT менять: код `1`.
Остальной текст беклога MUST оставаться побайтово неизменным.

#### Scenario: Остановка по ошибке окружения
- **WHEN** `forge stop` вызвана для операции `running` с причиной «раннер недоступен»
- **THEN** статус `stopped`, `stop_reason` содержит причину, задачи и отметки беклога не изменились

#### Scenario: Продолжение не остановленной операции
- **WHEN** `forge resume` вызвана для операции `running`
- **THEN** команда возвращает код `1`, беклог не изменён

#### Scenario: Повторная остановка
- **WHEN** `forge stop` вызвана для уже остановленной операции
- **THEN** код `0`, статус `stopped`, причина заменена новой

### Requirement: Закрытие успешной операции принимает модель в db
`forge close --operation <беклог>` при подтверждённой попытке MUST скопировать её `model.yaml`
в `db/model.yaml` и `changelog.yaml` в `db/changelog/<штамп>.yaml`, добавить `include` этого
файла в конец `db/changelog/master.yaml`, если его там нет, и поставить статус `success`.
Команда SHALL NOT коммитить.

#### Scenario: Первая успешная операция
- **WHEN** `db/` ещё нет, а попытка 2 подтверждена
- **THEN** появились `db/model.yaml`, `db/changelog/<штамп>.yaml` и `master.yaml` с одним `include`, статус `success`

#### Scenario: Принятый master накатывается
- **WHEN** после двух успешных операций накатывается `db/changelog/master.yaml` на пустую БД
- **THEN** Liquibase применяет changeset обеих операций в порядке их принятия

### Requirement: Закрытие после трёх неудач не меняет db
При вердикте `failure` у всех трёх попыток и подтверждённом `rollback.json` каждой
`forge close` MUST ставить статус `failure`, не трогая `db/`. Если нет ни подтверждённой попытки,
ни трёх неудач с подтверждённым откатом, команда SHALL возвращать код `1` с причиной и ничего
не менять.

#### Scenario: Три неудачи
- **WHEN** все три попытки неуспешны и откат каждой подтверждён
- **THEN** статус `failure`, содержимое `db/` не изменилось

#### Scenario: Закрывать рано
- **WHEN** у операции одна неуспешная попытка
- **THEN** команда возвращает код `1`, статус остаётся `running`

#### Scenario: Повторное закрытие
- **WHEN** `forge close` вызвана для уже закрытой операции
- **THEN** код `0`, статус и `db/` не изменились

### Requirement: Отчёт содержит всё для разбора исхода
`forge report --operation <беклог>` MUST печатать статус, число использованных попыток, пути
модели и changelog, перечень беклогов, а для каждой попытки — вердикт, расхождения сверки
из `reconcile.json` и итог отката из `rollback.json`. При `success` отчёт SHALL перечислять файлы
`db/` для коммита владельцем. Код `1` MUST возвращаться только при статусе `failure`.

#### Scenario: Отчёт об успехе
- **WHEN** операция закрыта со статусом `success` на второй попытке
- **THEN** отчёт называет две попытки, пути в `db/`, расхождения первой попытки, её откат и файлы для коммита, код `0`

#### Scenario: Отчёт о неудаче
- **WHEN** операция закрыта со статусом `failure`
- **THEN** отчёт содержит три попытки с расхождениями и откатом каждой, код `1`
