# Proposal

## Why

Выпуск 0.2.0 оставил открытыми пять задач, которые владелец ожидал увидеть закрытыми вместе
с выпуском: они были отложены, но это не было проговорено явно. Сценарий `release` о задачах
не знает и выпускает версию при любом их состоянии. Выпуск 0.3.0 включает все задачи, открытые
после 0.2.0, и должен состояться только тогда, когда каждая из них закрыта.

## What Changes

- Гейт задач выпуска в сценарии `release`: перед любой записью сценарий находит на GitHub
  milestone `vX.Y.Z` нового номера и завершается ошибкой, если milestone нет или в нём есть
  открытые задачи. Ошибка называет открытые задачи.
- Job `release` получает право `issues: read`; право записи по-прежнему только `contents: write`
  у того же job'а.
- `CONTRIBUTING.md`, раздел «Выпуск версии»: milestone как предусловие выпуска.
- Milestone `v0.3.0` на GitHub с задачами #7, #8, #9, #10, #12 и задачей этого change.
- Порядок выпуска 0.3.0: задачи #12 → #8 → #9 → #10 → #7, каждая своим change в ветке
  `release/v0.3.0`; PR в `main` закрывает их все, после слияния — `release` с разрядом `minor`.

Вне объёма: содержание самих задач #7, #8, #9, #10, #12 — у каждой свой change.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `forge-release`: релиз не выпускается, пока в milestone нового номера есть открытые задачи
  или milestone нет.

## Impact

- `.github/workflows/release.yml`: новый шаг и право `issues: read` у job'а `release`.
- `tests/release/test_release_workflow.py`: права job'а, порядок шагов, исполнение гейта
  с заглушкой `gh`.
- `CONTRIBUTING.md`, спека `forge-release`.
- GitHub: milestone `v0.3.0`, привязка задач, задача этого change — создаются по подтверждению.
- Каждый следующий выпуск требует milestone своего номера, в том числе `patch`.
