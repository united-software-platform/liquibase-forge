# Spec Delta

## MODIFIED Requirements

### Requirement: Статус операции читается из её беклога
`forge status --operation <беклог операции>` MUST печатать намерение, режим, признак согласия
на удаления `allow_drop`, статус операции, вердикт, беклог и каталог каждой попытки и номер
подтверждённой попытки. Подтверждённой SHALL считаться попытка с вердиктом `success`. Беклог
без поля `allow_drop` MUST давать `allow_drop: false`.

#### Scenario: Операция после первой неудачи
- **WHEN** у операции `verdict.attempt_1: failure`, остальные вердикты пусты
- **THEN** ответ называет статус `running`, одну использованную попытку и отсутствие подтверждённой попытки

#### Scenario: Беклога нет
- **WHEN** путь `--operation` не ведёт к беклогу операции
- **THEN** команда возвращает код `2`

#### Scenario: Признак согласия на удаления
- **WHEN** беклог операции содержит `mode: auto` и `allow_drop: true`
- **THEN** ответ называет режим `auto` и `allow_drop: true`

#### Scenario: Беклог прежнего шаблона
- **WHEN** беклог операции не содержит поля `allow_drop`
- **THEN** ответ называет `allow_drop: false`

### Requirement: Остановка и продолжение меняют только статус
`forge stop --operation <беклог> --reason <текст>` MUST переводить операцию из `running`
в `stopped` и записывать причину во фронтматтер. `forge resume --operation <беклог>` MUST
переводить `stopped` в `running`. Закрытую операцию ни одна из команд SHALL NOT менять: код `1`.
Остальной текст беклога MUST оставаться побайтово неизменным; единственное исключение — строка
`allow_drop` при продолжении с согласием на удаления.

#### Scenario: Остановка по ошибке окружения
- **WHEN** `forge stop` вызвана для операции `running` с причиной «раннер недоступен»
- **THEN** статус `stopped`, `stop_reason` содержит причину, задачи и отметки беклога не изменились

#### Scenario: Продолжение не остановленной операции
- **WHEN** `forge resume` вызвана для операции `running`
- **THEN** команда возвращает код `1`, беклог не изменён

#### Scenario: Повторная остановка
- **WHEN** `forge stop` вызвана для уже остановленной операции
- **THEN** код `0`, статус `stopped`, причина заменена новой

## ADDED Requirements

### Requirement: Продолжение операции может дать согласие на удаления
`forge resume --operation <беклог> --allow-drop` MUST для остановленной операции в режиме `auto`
переводить её в `running` и записывать `allow_drop: true` во фронтматтер беклога операции
и беклогов попыток, названных в `backlog.attempt_N`. Беклог без строки `allow_drop` SHALL получить
её после строки `mode`. Согласие SHALL NOT сниматься. Операцию в режиме `interactive` и операцию
не в статусе `stopped` команда с ключом SHALL NOT менять: код `1`.

#### Scenario: Согласие при продолжении
- **WHEN** операция в режиме `auto` остановлена, у неё `allow_drop: false`, и порождён беклог попытки 1
- **THEN** команда возвращает код `0`, статус `running`, беклог операции и беклог попытки 1 содержат `allow_drop: true`, прочие строки беклогов не изменились

#### Scenario: Беклог прежнего шаблона
- **WHEN** в беклоге остановленной операции `auto` нет строки `allow_drop`
- **THEN** строка `allow_drop: true` вставлена после строки `mode`

#### Scenario: Согласие уже дано
- **WHEN** у остановленной операции уже `allow_drop: true`
- **THEN** команда возвращает код `0`, статус `running`, `allow_drop` остаётся `true`

#### Scenario: Операция interactive
- **WHEN** ключ передан для остановленной операции в режиме `interactive`
- **THEN** команда возвращает код `1`, беклог не изменён

#### Scenario: Исполняемая операция
- **WHEN** ключ передан для операции в статусе `running`
- **THEN** команда возвращает код `1`, беклог не изменён


### Requirement: Отчёт перечисляет удаления итогового changelog
`forge report` MUST содержать `allow_drop` операции и перечень `destructive` — удаления
итогового changelog отчёта: принятого при `success`, иначе changelog последней начатой попытки.
Элемент перечня SHALL содержать таблицу и колонку; удалённая таблица MUST иметь `column: null`.
Нет итогового changelog или удалений в нём — перечень пуст.

#### Scenario: Успешная операция с удалениями
- **WHEN** операция закрыта со статусом `success`, а принятый changelog удаляет таблицу `invoice_line` и колонку `customer.email`
- **THEN** `destructive` содержит `{table: invoice_line, column: null}` и `{table: customer, column: email}`

#### Scenario: Операция без удалений
- **WHEN** итоговый changelog операции только создаёт таблицы
- **THEN** `destructive` — пустой перечень

#### Scenario: Попыток не было
- **WHEN** операция остановлена до первой попытки
- **THEN** `destructive` — пустой перечень
