# Design

## Context

Мотивация описана в proposal.md, раздел Why. Важные для решения факты текущего состояния:

- `docker/lbfr/docker-compose.yaml` подключается из `docker-compose.yml` секцией `include:`
  и поставляется в целевой проект без изменений. Переменные `.env` попадают в проект блоком
  `install/blocks/env.example`, корневой `.env.example` репозитория содержит тот же блок.
- Скрипты `tools/forge-env/*.sh` и шлюз `tools/liquibase/gateway.py` обращаются к сервисам
  по имени сервиса Compose (`docker compose up|run|ps <сервис>`). По имени контейнера обращается
  только `tools/ci/integration-env.sh:77` (`docker inspect … lbfr-db-test`).
- Сеть `lbfr-net` и том `lbfr-db-data` Compose сам дополняет именем проекта
  (`<проект>_lbfr-net`), конфликта у них нет.
- Цели `forge-env-*` агент запускает через раннер на хосте: рабочий каталог `make` — настоящий
  корень проекта. Внутри контейнера агента корень — `/app` (`PROJECT_DIR`).
- `forge-env-sync` сейчас только дописывает отсутствующие строки `FORGE_*`/`LBFR_*`
  из `.env.example` и не меняет существующие.
- CI создаёт `.env` из `.env.example` через `sed`, без `forge-env-sync`.

## Goals / Non-Goals

**Goals:**

- Окружения forge нескольких проектов работают на одном Docker-хосте одновременно.
- Конфликт имени или порта с другим проектом обнаруживается до `docker compose up`, и сообщение
  называет, что поменять.

**Non-Goals:**

- Автоматический выбор свободного хостового порта: порт по-прежнему выбирает владелец проекта
  из своего диапазона по DOCK-008. Forge только обнаруживает конфликт.
- Обнаружение порта, занятого процессом вне Docker. О нём по-прежнему сообщает сам демон
  при `up`.
- Переименование сервисов Compose и правка адресов БД.

## Decisions

### Префикс задаётся переменной `.env`, а не именем Compose-проекта

`container_name: ${LBFR_CONTAINER_PREFIX}-lbfr-db`. Значение лежит в `.env`, его видит владелец,
проверяет `forge-env-check`, и оно не зависит от того, как вызван Compose (`-p`, `COMPOSE_PROJECT_NAME`).

Альтернативы:

- **Убрать `container_name`.** Это вариант B, владелец его отклонил: имена `<проект>-lbfr-db-1`
  менее предсказуемы и расходятся с DOCK-002 сильнее.
- **Подставлять имя Compose-проекта** (`${COMPOSE_PROJECT_NAME}`). Отклонено: значение
  не хранится в проекте, его нельзя проверить в `forge-env-check` до разбора конфигурации, и оно
  меняется от ключа `-p`.

### Префикс выводится из имени корня проекта в `forge-env-sync`

Решение владельца. Из `basename` рабочего каталога берётся нижний регистр, каждая
последовательность символов вне `a-z0-9` заменяется на `-`, `-` по краям отбрасываются. Пустая
строка `LBFR_CONTAINER_PREFIX=` в `.env` заменяется на месте (`sed`). Общий механизм «дописать
отсутствующее» для остальных переменных не меняется: для префикса это отдельная ветка, потому что
в шаблоне значение пустое намеренно.

Если префикс получился пустым (имя каталога без латиницы и цифр), `sync` завершается кодом `1`
и не пишет ничего. Иначе пустое значение дало бы имя контейнера `-lbfr-db`, которое Docker
отвергает.

Альтернатива: только ручное задание с отказом `forge-env-check`. Отклонено владельцем, потому что
это лишний ручной шаг при каждой установке.

### Предварительная проверка в отдельном скрипте `tools/forge-env/preflight.sh`

`up.sh` вызывает `preflight.sh` сразу после `pull`/`build` и перед `up`. Скрипт:

1. Читает `docker compose config --format json`: имя проекта (`name`), `container_name`
   сервисов `lbfr-db` и `lbfr-db-test` и опубликованный порт `lbfr-db`. Так он не разбирает `.env`
   сам и видит те же значения, что и Compose.
1. Для каждого имени выполняет `docker ps -a --filter name=^/<имя>$` и читает метки
   `com.docker.compose.project` и `com.docker.compose.project.working_dir`. Если контейнер есть
   и его проект не совпадает с текущим, это конфликт.
1. Для порта выполняет `docker ps --filter publish=<порт>`, сравнение проектов то же.
1. При конфликте печатает все найденные конфликты и завершается кодом `1`. Контейнеры
   не трогает.

Отдельный скрипт позволяет проверить логику тестом без подъёма БД. Разбор JSON идёт через
`python3`, как в `check.sh`.

Альтернатива: разбирать ошибку `docker compose up`. Отклонено: текст ответа демона не является
контрактом, а `up` к этому моменту уже создаёт сеть.

### CI задаёт префикс явно и ищет контейнер через Compose

`integration-env.sh` добавляет в `sed` замену `^LBFR_CONTAINER_PREFIX=.*` на `lbfr-ci`
и получает идентификатор контейнера через `docker compose ps -q lbfr-db-test`. Имя хоста
в `/etc/hosts` остаётся `lbfr-db-test`: это адрес сервиса, а не имя контейнера.

### Исключение к DOCK-002 вносится здесь и в kit

Решение владельца. В `rules/docker.md` у DOCK-002 появляется исключение: сервисы инструмента,
который ставится в несколько проектов на одном хосте, задают `container_name` как
`${<ПРЕФИКС>}-<имя сервиса>`. Префикс берётся из `.env` и различается между проектами. Строка
DOCK-002 в таблице правил и таблица версий документа обновляются по DOC-022/DOC-024.
В `united-software-platform/sdd-developer-kit` заводится задача на то же исключение.

## Risks / Trade-offs

- [Сумма `rules/docker.md` разойдётся с `.sdd-kit-manifest.json`, и обновление kit'а отметит файл
  как правку владельца] → задача в kit. До её выпуска при обновлении kit'а правку сохраняют
  отказом от перезаписи. Это фиксируется в комментарии к issue #21.
- [`forge-env-sync`, запущенный внутри контейнера агента, а не через раннер, выведет префикс `app`]
  → цели `forge-env-*` штатно идут через раннер. В комментарии к переменной в `.env.example`
  сказано, что значение можно задать вручную.
- [Два проекта в каталогах с одинаковым именем получат одинаковый префикс] → у них совпадёт
  и имя Compose-проекта по умолчанию, то есть конфликт уже есть в самом Compose.
  `preflight.sh` конфликт имени в этом случае не увидит: проект тот же. Ограничение фиксируется
  в кейсе `docs/use-cases.md` со способом решения: задать префикс и `COMPOSE_PROJECT_NAME` вручную.
- [Порт, занятый процессом вне Docker, `preflight.sh` не обнаружит] → об этом сообщает демон при `up`.
  Это Non-Goal.
- [`docs/architecture.md` сейчас содержит незакоммиченные правки LBFR-028] → гейт GIT-020:
  перед правкой документа на этапе apply эти правки коммитятся отдельно либо правка откладывается
  до их коммита.

## Migration Plan

1. Обновить forge в проекте установщиком.
1. `make forge-env-sync`: в `.env` появляется `LBFR_CONTAINER_PREFIX=<имя каталога>`.
1. `make forge-env-up`: Compose видит изменённую конфигурацию сервисов и пересоздаёт контейнеры
   `lbfr-db` → `<префикс>-lbfr-db`, `lbfr-db-test` → `<префикс>-lbfr-db-test`. Том `lbfr-db-data`
   тот же, данные сохраняются.
1. Если второй проект на том же хосте использует тот же `FORGE_DB_HOST_PORT`, `preflight.sh`
   называет конфликт. Владелец меняет порт в `.env` одного из проектов.

Откат: вернуть прежнюю версию forge. Контейнеры пересоздадутся под литеральными именами,
переменная `LBFR_CONTAINER_PREFIX` в `.env` ничему не мешает.
