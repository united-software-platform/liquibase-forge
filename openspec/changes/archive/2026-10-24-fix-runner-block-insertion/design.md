# Design

## Context

Мотивация — в `proposal.md`, требования — в `specs/forge-delivery/spec.md`.

Сейчас блок `runner.py` ставится так:

- ветка `runner` функции `insert_block` в `install.sh` находит строку `^ALLOWED_TARGETS = frozenset\(`
  и вставляет фрагмент перед первой строкой, которая после среза отступа начинается с `}`;
- фрагмент `install/blocks/runner.py` — элементы множества с отступом 8 пробелов;
- если маркеры уже есть, содержимое между ними заменяется на месте, а статус блока (`same`,
  `update`, `owner`) считается по сумме содержимого и манифесту.

Петля воспроизведения из диагностики — временный проект kit `1.5.0` и `install.sh --source --yes`
с проверкой компиляции, состава `ALLOWED_TARGETS` и текста вне маркеров. Результаты на `v0.3.0`:

| Форма белого списка | `v0.3.0` | Якорь на словарь из тикета #18 |
|---|---|---|
| Однострочное множество (штатный kit `1.5.0`) | отказ, код `1` | отказ, код `1` |
| Словарь `TARGET_VARIABLES`, вывод `ALLOWED_TARGETS` из него | отказ, код `1` | вставка проходит |
| Многострочное множество | вставка проходит | отказ, код `1` |

Без проверки отступа закрывающей скобки якорь на словарь ставит блок внутрь `    }),` первой
многострочной записи, и `runner.py` перестаёт компилироваться.

## Goals / Non-Goals

**Goals:**

- Один фрагмент на все три формы белого списка, без ветвления по форме в установщике.
- Миграция блока, поставленного версиями до `0.3.1`, без ручных действий владельца.
- Тесты на дословном `runner.py` kit'а `v1.5.0`, а не на производной от файла репозитория forge.

**Non-Goals:**

- Разбор Python установщиком: место вставки ищется построчно средствами `sh`/`awk`, как сейчас.
- Поддержка `TARGET_VARIABLES`, объявленного после `ALLOWED_TARGETS` или неизменяемого.
- Загрузка архива forge без `curl`.

## Decisions

### Блок — оператор после присваивания, а не элементы литерала

Фрагмент [`install/blocks/runner.py`](../../../install/blocks/runner.py) записан без отступа:
комментарий о назначении целей, кортеж `_FORGE_TARGETS` с пятью целями forge, дописывание этих целей
с пустым множеством переменных в `TARGET_VARIABLES`, если словарь объявлен
(`if "TARGET_VARIABLES" in globals()`), и `ALLOWED_TARGETS = ALLOWED_TARGETS | frozenset(_FORGE_TARGETS)`.

Почему так: оператор не зависит от того, как записан литерал, и одинаково работает на трёх
формах. Объединение `|` даёт `frozenset`, так что тип `ALLOWED_TARGETS` для остального кода
раннера не меняется.

Во фрагменте нет строк из одних скобок: подсказка установщика о задвоении сравнивает строки
фрагмента с файлом целиком, и строка `)` совпала бы с концом многострочного литерала.

Отвергнуто:

- якорь на словарь из тикета #18 — чинит одну форму из трёх и ломает многострочную;
- три ветки с тремя фрагментами — для однострочного литерала пришлось бы переписывать текст
  вне маркеров, а это запрещено требованием о маркированных блоках;
- `try`/`except NameError` вместо `globals()` — то же поведение, но на две строки длиннее
  и с перехватом исключения ради проверки наличия имени.

### Место вставки — конец последнего присваивания `ALLOWED_TARGETS` верхнего уровня

Ветка `runner` ищет последнюю строку `^ALLOWED_TARGETS[ \t]*=` без отступа вне маркеров forge.
Концом оператора считается строка, на которой баланс скобок `([{` / `)]}` возвращается к нулю.
Скобки считаются после удаления строковых литералов в кавычках и комментариев `#`. Блок
вставляется сразу после этой строки. Если присваивания нет или баланс не сходится к концу
файла, ветка возвращает код `3`, и установщик отказывает, как сейчас.

Почему последнее присваивание: более позднее переприсваивание владельцем затёрло бы цели forge.
Почему баланс скобок: одно правило покрывает однострочный литерал, многострочный литерал
и `frozenset(TARGET_VARIABLES)`, а многострочные записи словаря выше присваивания не влияют.

### Найденный блок раннера всегда переставляется

Для `runner.py` при найденной паре маркеров установщик убирает строки от начального до конечного
маркера включительно и прогоняет вставку по оставшемуся тексту, как для отсутствующего блока.
Если блок уже стоял за присваиванием, результат совпадает с заменой на месте. Если он стоял внутри
литерала (установка `0.3.0` или раньше), блок переносится. Остальные четыре файла по-прежнему
заменяют блок на месте.

Статус по-прежнему считается по сумме прежнего содержимого блока и манифесту. Дополнительно для
`runner.py` статус `same` ставится только тогда, когда итоговый файл совпадает с текущим побайтно.
Иначе перенос неизменённого по тексту блока остался бы незамеченным.

Отвергнуто — отдельное распознавание «маркеры внутри литерала». Оно требует того же подсчёта
скобок, но с учётом строк блока, и даёт тот же результат, что безусловная перестановка.

### Подсказка ручной вставки называет место

`refuse_block` для `runner.py` печатает, куда ставить блок: отдельными строками без отступа
сразу после присваивания `ALLOWED_TARGETS`. Нынешнее сообщение с фрагментом-множеством вело
к `SyntaxError` в словарной форме (тикет #18, «Почему ручная вставка не помогает»).

### Собственный runner.py репозитория — штатный текст kit'а с новым блоком

Тексты вне маркеров в `tools/host-runner/runner.py` репозитория возвращаются к дословному файлу
kit'а `v1.5.0`, блок стоит за строкой `ALLOWED_TARGETS = ...`. Тогда фикстура `_kit_text`
в `tests/delivery/test_install.py` автоматически даёт штатную форму kit'а, а тесты
`test_blocks.py` и `test_installed_files_match_forge_repository` остаются в силе без изменений.

### Тесты трёх форм и миграции

В `tests/delivery/` появляются фикстуры `runner.py`:

- дословный файл kit'а `v1.5.0` (сумма `49a38d7e72f4…`, совпадает с `.sdd-kit-manifest.json`);
- многострочное множество;
- словарь `TARGET_VARIABLES` с многострочными записями `frozenset({...})`, закрытыми `    }),`;
- многострочное множество с блоком `0.3.0` внутри литерала, плюс манифест с его суммой.

Параметризованный тест ставит forge в проект с каждой формой и проверяет сценарии спецификации:
код `0`, компиляцию, состав `ALLOWED_TARGETS` и `TARGET_VARIABLES`, совпадение текста вне маркеров.
Состав читается загрузкой модуля без вызова `main()`. Тест
`test_unmarked_forge_differences_are_reported` переводится на строку нового фрагмента.

## Risks / Trade-offs

- [Скобки внутри строк, растянутых на несколько строк (тройные кавычки), в присваивании
  `ALLOWED_TARGETS`] → в известных формах их нет; при несходящемся балансе установщик отказывает
  с кодом `1` и подсказкой, файл не меняется.
- [`TARGET_VARIABLES` объявлен после `ALLOWED_TARGETS`] → блок его не видит, и записей forge
  в словаре нет. Ограничение называется в `CONTRIBUTING.md` в строке таблицы блоков.
- [Ручные записи forge старого вида (`"liquibase-update",`) без маркеров больше не ловятся
  подсказкой о задвоении] → повторный элемент множества безвреден, проверка остаётся для строк
  нового фрагмента.
- [Модульное имя `_FORGE_TARGETS` появляется в пространстве имён раннера] → префикс `_`,
  коллизий с kit'ом `1.5.0` нет.

## Migration Plan

1. Владелец проекта на forge `0.3.0` запускает `sh install.sh --ref v0.3.1`. Блок `runner.py`
   в плане отмечен как обновляемый, после записи он стоит за присваиванием.
2. Раннер на хосте перезапускается, как после любой установки.
3. Откат — `sh install.sh --ref v0.3.0`. На штатном kit'е `1.5.0` он снова откажет, поэтому
   откат имеет смысл только для проектов с многострочным литералом.
