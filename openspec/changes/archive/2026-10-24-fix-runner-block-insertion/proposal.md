# Proposal

## Why

Установщик `install.sh` (`v0.3.0`) не ставит forge ни в один проект на SDD Developer Kit `1.5.0`,
хотя именно эту версию kit требует как минимальную. Ветка `runner` ищет многострочное множество
`ALLOWED_TARGETS = frozenset({` … `})`. Штатный `tools/host-runner/runner.py` kit'а `v1.5.0`
(сумма `49a38d7e…`, совпадает с манифестом kit'а) задаёт белый список одной строкой —
`ALLOWED_TARGETS = frozenset({"init", "openspec-init", "help"})`. Проекты, где владелец перевёл
белый список на словарь `TARGET_VARIABLES`, тоже отказываются. Установка завершается кодом `1`
с сообщением «не найдено место вставки блока forge» (тикеты #17 и #18, задача LBFR-027).

Дефект прошёл тесты, потому что фикстура `tests/delivery/test_install.py` строит «файл kit'а»
из собственного `runner.py` репозитория forge. Там белый список уже переписан многострочным
литералом, а штатную однострочную форму kit'а тесты не видели. Исправление из тикета #18 — якорь
на словарь — чинит только словарную форму и ломает многострочную. Поэтому владелец выбрал
универсальный блок.

## What Changes

- Блок forge в `tools/host-runner/runner.py` становится отдельным оператором Python верхнего
  уровня сразу после присваивания `ALLOWED_TARGETS`. Он расширяет множество целями forge
  и дописывает их в словарь `TARGET_VARIABLES` без переменных, если такой словарь есть.
  Литерал белого списка блок больше не трогает.
- Место вставки распознаётся для трёх форм белого списка: однострочное множество kit'а `1.5.0`,
  многострочное множество, производное от словаря `TARGET_VARIABLES`.
- Блок, вставленный прежними версиями внутрь литерала, при повторной установке переносится
  за присваивание. Текст вне маркеров по-прежнему не меняется.
- **BREAKING** для владельцев, правивших блок вручную: фрагмент `install/blocks/runner.py`
  меняет форму с элементов множества на оператор. Правка владельца, как и раньше, перезаписывается
  только с согласия или с `--yes`.
- Собственный `runner.py` репозитория forge приводится к штатному тексту kit'а `1.5.0` с новым
  блоком. Тесты установщика получают фикстуры трёх форм, включая дословный `runner.py` kit'а `v1.5.0`.
- Выпуск `0.3.1`. В тикетах #18 и #17 фиксируется принятое решение, оба тикета закрываются.

Вне объёма: загрузка архива без `curl` в контейнере агента (раздел «Попутно» тикета #18). Если
она нужна, её стоит завести отдельной задачей.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `forge-delivery`: требование «Отсутствующий блок вставляется заново» уточняется. Место вставки
  блока раннера определяется по присваиванию `ALLOWED_TARGETS` любой из трёх форм, блок — оператор
  после присваивания, а блок внутри литерала переносится при повторной установке.

## Impact

- `install.sh` — ветка `runner` функции `insert_block` и обработка найденных маркеров для `runner.py`.
- `install/blocks/runner.py` — новая форма фрагмента.
- `tools/host-runner/runner.py` репозитория — текст вне маркеров возвращается к поставке kit'а
  `1.5.0`, блок стоит за присваиванием.
- `tests/delivery/test_install.py`, новые фикстуры `runner.py` в `tests/delivery/`.
- `CONTRIBUTING.md` — строка таблицы блоков о `runner.py`.
- `VERSION` и GitHub: milestone `v0.3.1`, тикеты #17 и #18.
- Установленные проекты: при обновлении forge до `0.3.1` блок раннера переносится. После установки
  раннер на хосте нужно перезапустить, как и сейчас.
