# Spec Delta

## MODIFIED Requirements

### Requirement: Отчёт содержит всё для разбора исхода
`forge report --operation <беклог>` MUST печатать статус, число использованных попыток, пути
модели и changelog, перечень беклогов, а для каждой попытки — вердикт, расхождения сверки
из `reconcile.json` и итог отката из `rollback.json`. Для закрытой операции отчёт SHALL
перечислять файлы для коммита: след операции, а при `success` — и файлы корня принятого
состояния. Код `1` MUST возвращаться только при статусе `failure`.

#### Scenario: Отчёт об успехе
- **WHEN** операция закрыта со статусом `success` на второй попытке
- **THEN** отчёт называет две попытки, пути в корне принятого состояния, расхождения первой попытки, её откат и файлы для коммита, код `0`

#### Scenario: Отчёт о неудаче
- **WHEN** операция закрыта со статусом `failure`
- **THEN** отчёт содержит три попытки с расхождениями и откатом каждой, код `1`

#### Scenario: Отчёт при корне вне db
- **WHEN** `FORGE_ACCEPTED_DIR=.forge/db`, а операция закрыта со статусом `success`
- **THEN** файлы для коммита названы путями в `.forge/db/`

#### Scenario: След успешной операции для коммита
- **WHEN** операция `20261017-153000` закрыта со статусом `success` на второй попытке
- **THEN** файлы для коммита — файлы корня принятого состояния, каталог `backlog/forge-model/20261017-153000/` и каталоги `backlog/forge-apply/20261017-153000-1/` и `backlog/forge-apply/20261017-153000-2/`

#### Scenario: След неудачной операции для коммита
- **WHEN** операция `20261017-153000` закрыта со статусом `failure`
- **THEN** файлы для коммита — каталог операции и каталоги беклогов трёх попыток, файлов корня принятого состояния среди них нет

#### Scenario: Открытая операция
- **WHEN** операция в статусе `running` либо `stopped`
- **THEN** отчёт не перечисляет файлов для коммита
