# Proposal

## Why

Открытую операцию forge нельзя бросить. `forge close` закрывает её только с `success` или после трёх неудач
с подтверждённым откатом, а пока операция открыта, навык не принимает новое намерение. Владелец, который
отказал на стоп-знаке и передумал, может только довести операцию до конца. При подготовке 0.2.0 (LBFR-018)
это записали в «Ограничения» `README.md`, а саму команду отложили. Задача #10 (LBFR-022) входит в выпуск 0.3.0.

## What Changes

- **Новый статус `abandoned`.**
  - Операция закрыта по решению владельца, ничего не принято.
  - Статус закрытый наравне с `success` и `failure`: `forge status --latest` такую операцию не находит,
    `stop` и `resume` её не меняют.
- **Новая команда `forge abandon --operation <беклог> --reason <текст>`:**
  - принимает операцию `running` или `stopped`;
  - откатывает каждую начатую попытку, у которой нет подтверждённого отката (`rollback.json` с `verified: true`),
    в том числе попытку с вердиктом `success`. Откат тот же, что у `forge rollback`, вместе с проверкой
    возврата и запасным путём;
  - если все откаты подтверждены — ставит `abandoned` и пишет причину;
  - иначе — код `1`, статус прежний.

  Коды возврата:

  | Код | Когда |
  |-----|-------|
  | `0` | Брошена или уже была брошена |
  | `1` | Операция закрыта с `success`/`failure`, либо откат не подтверждён |
  | `2` | Ошибки окружения и беклога, как у `forge rollback` |

- **`forge rollback` при отказе.** Сценарий отката получает признак отказа: с ним попытка с вердиктом `success`
  откатывается, а не пропускается. Ключ `forge rollback` для пользователя не появляется: признак
  ставит только `forge abandon`.
- **`forge report` для `abandoned`:**
  - код `0`, статус и причина;
  - откат каждой попытки;
  - `commit.files` — след операции и беклоги попыток без файлов корня принятого состояния, как при `failure`.
- **Навык `forge`, ключ `--abandon "<причина>"`.**
  - Бросает единственную открытую операцию из `forge status --latest` в обоих режимах: сам вызов и есть
    решение владельца, стоп-знака нет.
  - Возвращает отчёт и файлы для коммита. Следующий `/forge` с намерением начинает новую операцию.
  - Без открытой операции ключ отклоняется с сообщением. Вместе с намерением, `--mode` или `--allow-drop`
    ключ не принимается.
- **Шаблон `forge-model`:** правило остановки называет `/forge --abandon` как выход для владельца,
  который передумал.
- **Документы:**
  - `docs/operation.md` — статусы, диаграмма, таблица команд, исход отказа, отчёт, файлы для коммита;
  - `docs/domain.md` — статус операции;
  - `docs/migration.md` — откат при отказе;
  - `docs/use-cases.md` — кейс 13 «Хочу бросить открытую операцию»;
  - `README.md` — пункт «Открытую операцию нельзя бросить» убирается из «Ограничений», шаг 4 ссылается
    на новый кейс.
- **Интеграционный тест:** после отказа от операции с накатанной попыткой схема тестовой БД совпадает
  с принятой моделью (`forge reconcile` без расхождений), принятое состояние не изменилось, `forge status --latest`
  отвечает `operation: null`.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `forge-operation-commands`:
  - новое требование — команда отказа;
  - отчёт и `status --latest` учитывают статус `abandoned`.
- `forge-operation`:
  - новое требование — навык бросает операцию по ключу `--abandon`;
  - требования о завершённости беклога и о файлах для коммита учитывают новый исход.
- `forge-migration`: откат подтверждённой попытки допускается при отказе от операции.

## Impact

- **Код:**
  - `src/forge/operation/domain/operation.py` — статус, переход `abandon`, ошибки;
  - новый сценарий `abandon_operation` в `src/forge/operation/application/`;
  - `src/forge/migration/application/rollback_attempt/` — признак отказа во входном контракте;
  - команда `src/forge/cli/commands/abandon.py` и её регистрация;
  - отчёт `build_report`.
- **Навык и шаблон:** `.claude/skills/forge/SKILL.md`, `templates/forge-model.md`.
- **Документы:** `docs/operation.md`, `docs/domain.md`, `docs/migration.md`, `docs/use-cases.md`, `README.md`.
- **Тесты:**
  - модульные тесты агрегата, сценария, отката и отчёта;
  - CLI-тест кодов;
  - интеграционный тест отказа на `lbfr-db-test` с раннером.
- **Совместимость:**
  - беклоги прежних версий читаются без изменений;
  - новый статус пишется только командой отказа;
  - CLI-контракт остальных команд не меняется.
- **Зависимость:** change `document-failure-and-removal` (#9) добавляет кейсы 11–12. Этот change идёт после
  него, добавляет кейс 13 и уточняет в кейсе 11 выход при неподтверждённом откате.
