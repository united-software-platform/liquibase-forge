## ADDED Requirements

### Requirement: Навык бросает открытую операцию по просьбе владельца
Навык `forge` MUST принимать ключ `--abandon "<причина>"` и бросать единственную открытую операцию
командой `forge abandon` с этой причиной. Ключ SHALL действовать одинаково в режимах `interactive`
и `auto`: вызов с ключом и есть решение владельца, отдельного стоп-знака нет. После отказа навык MUST
вернуть LLM отчёт `forge report` и файлы для коммита. Навык MUST NOT бросать операцию
по собственному решению.

#### Scenario: Отказ от остановленной операции
- **WHEN** операция `stopped` после отказа владельца на стоп-знаке, и навык вызван с `--abandon "передумал"`
- **THEN** операция в статусе `abandoned`, LLM получает отчёт с причиной «передумал» и файлы для коммита

#### Scenario: Новое намерение после отказа
- **WHEN** открытая операция брошена, и навык вызван с новым намерением
- **THEN** порождён беклог новой операции с этим намерением

#### Scenario: Откат не подтверждён
- **WHEN** `forge abandon` возвращает код `1`, потому что откат попытки не подтверждён
- **THEN** операция остаётся открытой, а LLM получает причину и отчёт

### Requirement: Ключ отказа применяется только к открытой операции
Если открытой операции нет, навык MUST отклонить ключ `--abandon` с сообщением LLM, не вызывая команд,
меняющих статус. Вместе с намерением, `--mode` или `--allow-drop` ключ SHALL NOT приниматься.

#### Scenario: Отказ без открытой операции
- **WHEN** навык вызван с `--abandon`, а открытых операций нет
- **THEN** ни одна команда, меняющая статус, не вызвана, и LLM получает сообщение, что бросать нечего

#### Scenario: Отказ вместе с намерением
- **WHEN** навык вызван с `--abandon "передумал"` и намерением
- **THEN** ключ отклонён с сообщением LLM, операция не брошена и новая не начата

## MODIFIED Requirements

### Requirement: Беклог операции завершён при любом исходе
После закрытия со статусом `success` или `failure` беклог операции и все беклоги попыток MUST
проходить проверку полноты исполнения `backlog verify` с кодом `0`. Беклог брошенной операции
(`abandoned`) SHALL NOT обязан проходить эту проверку: исполнение прервано решением владельца,
и невыполненные задачи остаются невыполненными.

#### Scenario: Проверка после неудачи
- **WHEN** операция закрыта со статусом `failure`
- **THEN** `backlog verify` по беклогу операции и по каждому беклогу попытки возвращает `0`

#### Scenario: Брошенная операция
- **WHEN** операция брошена на стоп-знаке перед накатом первой попытки
- **THEN** статус `abandoned` записан, а задачи наката и закрытия в беклоге остаются неотмеченными

### Requirement: Навык называет файлы для коммита
По закрытии операции со статусом `success`, `failure` или `abandoned` навык `forge` MUST вернуть LLM
перечень файлов для коммита из отчёта `forge report`: след операции и при `success` файлы корня
принятого состояния. Навык SHALL NOT коммитить: коммит делает владелец.

#### Scenario: Успешная операция
- **WHEN** операция закрыта со статусом `success`
- **THEN** LLM получает файлы корня принятого состояния и каталоги следа операции и её попыток как файлы для коммита

#### Scenario: Неудачная операция
- **WHEN** операция закрыта со статусом `failure`
- **THEN** LLM получает каталоги следа операции и её попыток как файлы для коммита, а файлов корня принятого состояния среди них нет

#### Scenario: Брошенная операция
- **WHEN** операция брошена со статусом `abandoned`
- **THEN** LLM получает каталоги следа операции и её начатых попыток как файлы для коммита, а файлов корня принятого состояния среди них нет

#### Scenario: Остановленная операция
- **WHEN** исполнение остановлено, и операция в статусе `stopped`
- **THEN** LLM получает отчёт без файлов для коммита
