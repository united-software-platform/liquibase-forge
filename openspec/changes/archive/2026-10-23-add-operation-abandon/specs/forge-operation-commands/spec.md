## ADDED Requirements

### Requirement: Отказ закрывает открытую операцию без принятия
`forge abandon --operation <беклог> --reason <текст>` MUST закрывать операцию в статусе `running`
или `stopped` статусом `abandoned` и записывать причину во фронтматтер. Перед закрытием команда MUST
откатить каждую начатую попытку без подтверждённого отката, включая попытку с вердиктом `success`.
Если хотя бы один откат не подтверждён, команда MUST вернуть код `1` и оставить статус прежним.
Корень принятого состояния команда SHALL NOT менять ни при каком исходе.

#### Scenario: Отказ после наката
- **WHEN** у операции `running` первая попытка накатана, её вердикт `success`, а операция не закрыта
- **THEN** накат попытки откатан, `rollback.json` попытки подтверждает возврат, статус `abandoned`, корень принятого состояния не изменился, код `0`

#### Scenario: Отказ от остановленной операции без наката
- **WHEN** операция `stopped` на стоп-знаке перед созданием модели первой попытки
- **THEN** статус `abandoned`, причина записана, схема БД не изменилась, код `0`

#### Scenario: Откат не подтверждён
- **WHEN** откат накатанной попытки не прошёл проверку возврата
- **THEN** команда возвращает код `1` с причиной, статус операции прежний

#### Scenario: Новая операция после отказа
- **WHEN** единственная открытая операция брошена
- **THEN** `forge status --latest` отвечает `operation: null`

### Requirement: Отказ не меняет закрытую операцию
Операцию со статусом `success` или `failure` команда `forge abandon` SHALL NOT менять: код `1`.
Повторный отказ от брошенной операции SHALL возвращать код `0` и ничего не менять. Нечитаемый беклог
и ошибки окружения MUST давать код `2` без изменения статуса.

#### Scenario: Закрытая операция
- **WHEN** `forge abandon` вызвана для операции со статусом `success`
- **THEN** команда возвращает код `1`, беклог и корень принятого состояния не изменены

#### Scenario: Повторный отказ
- **WHEN** `forge abandon` вызвана для операции `abandoned`
- **THEN** код `0`, беклог не изменён

#### Scenario: Раннер недоступен
- **WHEN** откат накатанной попытки требует шлюза, а раннер не отвечает
- **THEN** команда возвращает код `2`, статус операции прежний

## MODIFIED Requirements

### Requirement: Отчёт содержит всё для разбора исхода
`forge report --operation <беклог>` MUST печатать статус, число использованных попыток, пути
модели и changelog, перечень беклогов, а для каждой попытки — вердикт, расхождения сверки
из `reconcile.json` и итог отката из `rollback.json`. Для закрытой операции отчёт SHALL
перечислять файлы для коммита: след операции, а при `success` — и файлы корня принятого
состояния. Для брошенной операции отчёт SHALL называть причину отказа. Код `1` MUST возвращаться
только при статусе `failure`.

#### Scenario: Отчёт об успехе
- **WHEN** операция закрыта со статусом `success` на второй попытке
- **THEN** отчёт называет две попытки, пути в корне принятого состояния, расхождения первой попытки, её откат и файлы для коммита, код `0`

#### Scenario: Отчёт о неудаче
- **WHEN** операция закрыта со статусом `failure`
- **THEN** отчёт содержит три попытки с расхождениями и откатом каждой, код `1`

#### Scenario: Отчёт при корне вне db
- **WHEN** `FORGE_ACCEPTED_DIR=.forge/db`, а операция закрыта со статусом `success`
- **THEN** файлы для коммита названы путями в `.forge/db/`

#### Scenario: След успешной операции для коммита
- **WHEN** операция `20261017-153000` закрыта со статусом `success` на второй попытке
- **THEN** файлы для коммита — файлы корня принятого состояния, каталог `backlog/forge-model/20261017-153000/` и каталоги `backlog/forge-apply/20261017-153000-1/` и `backlog/forge-apply/20261017-153000-2/`

#### Scenario: След неудачной операции для коммита
- **WHEN** операция `20261017-153000` закрыта со статусом `failure`
- **THEN** файлы для коммита — каталог операции и каталоги беклогов трёх попыток, файлов корня принятого состояния среди них нет

#### Scenario: Отчёт о брошенной операции
- **WHEN** операция `20261017-153000` брошена после первой попытки с причиной «передумал»
- **THEN** отчёт называет статус `abandoned`, причину «передумал» и откат первой попытки; файлы для коммита — каталог операции и каталог `backlog/forge-apply/20261017-153000-1/` без файлов корня принятого состояния; код `0`

#### Scenario: Открытая операция
- **WHEN** операция в статусе `running` либо `stopped`
- **THEN** отчёт не перечисляет файлов для коммита

### Requirement: Остановка и продолжение меняют только статус
`forge stop --operation <беклог> --reason <текст>` MUST переводить операцию из `running`
в `stopped` и записывать причину во фронтматтер. `forge resume --operation <беклог>` MUST
переводить `stopped` в `running`. Закрытую операцию — со статусом `success`, `failure` или
`abandoned` — ни одна из команд SHALL NOT менять: код `1`. Остальной текст беклога MUST оставаться
побайтово неизменным; единственное исключение — строка `allow_drop` при продолжении с согласием
на удаления.

#### Scenario: Остановка по ошибке окружения
- **WHEN** `forge stop` вызвана для операции `running` с причиной «раннер недоступен»
- **THEN** статус `stopped`, `stop_reason` содержит причину, задачи и отметки беклога не изменились

#### Scenario: Продолжение не остановленной операции
- **WHEN** `forge resume` вызвана для операции `running`
- **THEN** команда возвращает код `1`, беклог не изменён

#### Scenario: Повторная остановка
- **WHEN** `forge stop` вызвана для уже остановленной операции
- **THEN** код `0`, статус `stopped`, причина заменена новой

#### Scenario: Продолжение брошенной операции
- **WHEN** `forge resume` вызвана для операции `abandoned`
- **THEN** команда возвращает код `1`, беклог не изменён
