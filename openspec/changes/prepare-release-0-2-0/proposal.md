# Proposal

## Why

Ветка `release/v0.2.0` несёт установщик, связи, удаления и версионирование, но в `main` её нет:
сценарий `release` не запускается, установщик по ссылке из `README.md` недоступен, тегов и
релизов нет. Аудит перед выпуском (задача LBFR-018, GitHub #6) нашёл документы, описывающие
не то, что поставляется, и ни одной автоматической проверки в GitHub Actions — релиз сегодня
выпускается с любого коммита `main`, даже с красными тестами.

## What Changes

- Новый workflow `.github/workflows/checks.yml`: на `pull_request` и `push` в `main` прогоняет
  линтер, форматирование, типы, тесты без интеграционных и объём секций `Makefile` — те же
  команды, что раздел «Проверки» `CONTRIBUTING.md`.
- `release.yml` вызывает `checks` первым job'ом: номер версии повышается только после пройденных
  проверок на коммите `main`. Права `contents: write` сужаются до job'а выпуска.
- `BUSINESS-REQUIREMENTS.md`: границы поставки приводятся к действующему поведению — удаление
  таблиц, колонок и ограничений поддерживается, смена типа, NULL и первичного ключа нет.
- `README.md`: в «Ограничениях» — ограничения продукта (DOC-020); `--ref v0.2.0` заменяется
  на `--ref vX.Y.Z`; пересказ перечня файлов с блоками forge уходит (DGN-011).
- `CONTRIBUTING.md`: проверки в CI, связь с выпуском, поведение интеграционных тестов при
  настроенном, но недоступном раннере.
- `docs/use-cases.md`: кейсы «обновить forge до новой версии» и «разрешить удаления в `auto`».
- Спеки: Purpose `forge-delivery` и `forge-migration` переписываются, требования `forge-migration`
  с устаревшими «добавляющей разницей» и «неаддитивными изменениями» переименовываются.
- Выпуск `v0.2.0`: PR `release/v0.2.0` → `main`, запуск `release` с разрядом `minor`, текст релиза.

Вне объёма: интеграционные тесты в CI (LBFR-019, #7), защита `main` с обязательным `checks`
(LBFR-020, #8), кейсы разбора `failure` и удаления forge (LBFR-021, #9).

## Capabilities

### New Capabilities

- `forge-checks`: автоматические проверки репозитория forge в GitHub Actions — триггеры, состав
  проверок, совпадение с локальными командами, пропуск интеграционных тестов.

### Modified Capabilities

- `forge-release`: релиз не выпускается без пройденных проверок; права записи принадлежат
  только job'у выпуска.
- `forge-migration`: переименование двух требований — «Changelog строится из разницы моделей»
  и «Неподдерживаемые изменения отклоняются»; текст требований не меняется.

## Impact

- **CI:** новый `.github/workflows/checks.yml`, правка `.github/workflows/release.yml`.
- **Тесты:** `tests/release/test_release_workflow.py` — права и порядок job'ов; новый тест
  workflow `checks` — триггеры и совпадение команд с разделом «Проверки» `CONTRIBUTING.md`.
- **Документы:** `README.md`, `CONTRIBUTING.md`, `docs/use-cases.md`, `BUSINESS-REQUIREMENTS.md`.
- **Спеки:** `openspec/specs/forge-delivery/spec.md` и `forge-migration/spec.md` — Purpose.
- **Код CLI и поставка не меняются:** `delivery.txt` не затрагивается, workflow в поставку
  не входят.
- **GitHub:** PR в `main`, запуск `release`, GitHub Release `v0.2.0`.
