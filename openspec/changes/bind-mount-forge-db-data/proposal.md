# Proposal

## Why

Данные целевой БД `lbfr-db` лежат в именованном томе Docker `lbfr-db-data`: из каталога проекта
их не видно, имя тома зависит от имени Compose-проекта — при совпадающих именах каталогов два
проекта делят один том, при смене `COMPOSE_PROJECT_NAME` данные «пропадают», — а удаление forge
требует отдельно искать и удалять том. Хранение данных в каталоге проекта `data/lbfr-db` привязывает
их к проекту, а не к имени Compose-проекта (задача LBFR-030, issue #24).

## What Changes

- Сервис `lbfr-db` монтирует каталог проекта `./data/lbfr-db` в `/var/lib/postgresql/data`
  вместо именованного тома.
- **BREAKING** Объявление тома `lbfr-db-data` удаляется из `docker/lbfr/docker-compose.yaml`.
  В существующей установке после обновления `lbfr-db` стартует на пустом каталоге: данные прежнего
  тома автоматически не переносятся, перенос описывается кейсом документа кейсов.
- `make forge-env-up` создаёт `data/lbfr-db` до запуска контейнеров, чтобы каталог не создавал
  демон Docker от имени `root`.
- `data/lbfr-db/` исключается из git: в `.gitignore` репозитория forge и в блоке forge `.gitignore`
  целевого проекта (`install/blocks/gitignore`). Остальной каталог `data/` проекта forge не трогает.
- Документ кейсов: кейсы 2, 12 и 14 переводятся с тома на каталог, добавляется кейс переноса
  данных из прежнего тома.
- Сервер тестов `lbfr-db-test` не меняется: он работает на `tmpfs`.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `forge-environment`: добавляются требования о хранении данных целевой БД в каталоге проекта
  `data/lbfr-db`, о создании каталога целью `make forge-env-up` и об исключении каталога из git.

## Impact

- `docker/lbfr/docker-compose.yaml` — монтирование `lbfr-db`, удаление секции `volumes`.
- `tools/forge-env/up.sh` — создание каталога данных.
- `.gitignore`, `install/blocks/gitignore` — строка `/data/lbfr-db/`; блок поставляется
  повторной установкой forge.
- `docs/use-cases.md` — кейсы 2, 12, 14 и новый кейс переноса данных.
- Тесты: `tests/tools/test_forge_env.py` (порядок шагов `up.sh`), `tests/delivery/test_blocks.py`
  (совпадение блока с фрагментом) — проверяются прогоном.
- Существующие установки: данные тома `<проект>_lbfr-db-data` остаются в Docker до ручного переноса
  или удаления.
