# Spec Delta

## ADDED Requirements

### Requirement: Внешние ключи сверяются по содержимому
Сверка MUST читать внешние ключи таблиц схемы `public` интроспекцией каталога и сравнивать
их с моделью по колонкам FK, целевой таблице и колонкам цели в парном порядке. FK модели,
которого нет в БД, SHALL давать `foreign_key_missing`; FK в БД, которого нет в модели, —
`foreign_key_unexpected`. Имя ограничения MUST NOT сравниваться.

#### Scenario: Внешний ключ совпадает
- **WHEN** в БД есть FK `invoice.customer_id` → `customer.id` с произвольным именем, и он объявлен в модели
- **THEN** расхождений по внешним ключам нет

#### Scenario: Внешнего ключа нет в БД
- **WHEN** модель объявляет FK `invoice.customer_id` → `customer.id`, а в БД его нет
- **THEN** перечень содержит `foreign_key_missing` для таблицы `invoice`

#### Scenario: Лишний внешний ключ
- **WHEN** в БД есть FK, которого нет в модели
- **THEN** перечень содержит `foreign_key_unexpected` для его таблицы

#### Scenario: Отсутствующая таблица
- **WHEN** таблицы модели `invoice` с FK в БД нет
- **THEN** перечень содержит `table_missing` для `invoice` и не содержит расхождений её внешних ключей

### Requirement: Наборы уникальности сверяются по составу
Сверка MUST читать ограничения уникальности таблиц схемы `public` и сравнивать их с наборами
`unique` модели по составу колонок. Набор модели, которого нет в БД, SHALL давать
`unique_missing`; ограничение в БД, которого нет в модели, — `unique_unexpected`. Имя
ограничения и уникальные индексы без ограничения MUST NOT сравниваться.

#### Scenario: Набор совпадает
- **WHEN** модель объявляет `unique: [[tenant_id, code]]`, а в БД ограничение по `code, tenant_id`
- **THEN** расхождений по уникальности нет

#### Scenario: Набора нет в БД
- **WHEN** модель объявляет `unique: [[email]]` у `customer`, а ограничения в БД нет
- **THEN** перечень содержит `unique_missing` для `customer`

### Requirement: Расхождения ограничений идут в устойчивом порядке
Расхождения ограничений таблицы MUST следовать за расхождением её первичного ключа: наборы
уникальности модели по порядку, лишние наборы, внешние ключи модели по порядку, лишние внешние
ключи; лишние ограничения — в порядке их описания колонками.

#### Scenario: Повторная сверка
- **WHEN** сверка с расхождениями ограничений дважды выполнена на неизменной БД
- **THEN** перечни расхождений совпадают
