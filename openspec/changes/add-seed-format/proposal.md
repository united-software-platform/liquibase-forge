# Proposal

## Why

Forge строит и подтверждает только структуру схемы, а заполнить справочные таблицы (статусы, типы,
роли) ему нечем: модель описывает таблицы и ограничения, но не строки. Это первая из четырёх частей
операции seed (LBFR-028, #20). Сначала нужен формат файла seed и его проверка до наката: от них
зависят построение changelog данных, сверка строк и сама операция.

## What Changes

- Новый формат файла `seed.yaml` версии `1`. Файл задаёт полное целевое состояние строк
  справочных таблиц: таблица из seed принадлежит ему целиком, строка идентифицируется полным
  первичным ключом, значения явные и записаны по типам модели.
- Новая команда `forge validate-seed --seed <путь> [--model <путь>]`. Она проверяет seed
  по модели данных (по умолчанию — по принятой модели корня принятого состояния) и печатает все
  нарушения сразу с путями и кодами, по образцу `forge validate`.
- Проверка охватывает структуру файла, принадлежность таблиц и колонок модели, типы и диапазоны
  значений, NOT NULL, уникальность первичного ключа и наборов `unique`, ссылки внешних ключей
  только на строки таблиц seed и циклы ссылок между строками.
- Новый документ `docs/seed-format.md` с примером, который тест сверяет с фикстурой.
- Changelog данных, накат, откат, сверка и операция в это изменение не входят. Это изменения
  `add-seed-migration`, `add-seed-reconciliation` и `add-seed-operation`.

## Capabilities

### New Capabilities

- `forge-seed-data`: формат файла seed справочных данных и его проверка командой
  `forge validate-seed` по модели данных.

### Modified Capabilities

Нет. Формат модели и `forge validate` не меняются: seed читает модель через существующий сценарий
загрузки.

## Impact

- Код: новый ограниченный контекст `src/forge/seeding/` (домен, приложение, инфраструктура),
  новая подкоманда CLI `src/forge/cli/commands/validate_seed.py` и её регистрация в `main.py`.
  Контекст «Моделирование» не меняется.
- Тесты: `tests/seeding/` и `tests/cli/test_validate_seed.py`, фикстура
  `tests/fixtures/seed/example.yaml`.
- Документация: `docs/seed-format.md`, строка команды в таблице команд `docs/architecture.md`,
  понятия seed в `docs/domain.md`.
- Зависимости: новых нет, разбор YAML — тот же `PyYAML`.
