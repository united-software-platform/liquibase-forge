# Spec Delta

## MODIFIED Requirements

### Requirement: Остановка и продолжение меняют только статус

`forge stop --operation <беклог> --reason <текст>` MUST переводить операцию из `running`
в `stopped` и записывать причину во фронтматтер. `forge resume --operation <беклог>` MUST
переводить `stopped` в `running`. Закрытую операцию — со статусом `success`, `failure` или
`abandoned` — ни одна из команд SHALL NOT менять: код `1`. Остальной текст беклога MUST оставаться
побайтово неизменным; единственное исключение — строка `allow_drop` при продолжении с согласием
на удаления.

#### Scenario: Остановка по ошибке окружения

- **WHEN** `forge stop` вызвана для операции `running` с причиной «Liquibase недоступен»
- **THEN** статус `stopped`, `stop_reason` содержит причину, задачи и отметки беклога не изменились

#### Scenario: Продолжение не остановленной операции

- **WHEN** `forge resume` вызвана для операции `running`
- **THEN** команда возвращает код `1`, беклог не изменён

#### Scenario: Повторная остановка

- **WHEN** `forge stop` вызвана для уже остановленной операции
- **THEN** код `0`, статус `stopped`, причина заменена новой

#### Scenario: Продолжение брошенной операции

- **WHEN** `forge resume` вызвана для операции `abandoned`
- **THEN** команда возвращает код `1`, беклог не изменён

## REMOVED Requirements

### Requirement: Статус проверяет тестовую среду

**Reason**: Сценарий «Раннер не отвечает» устарел: проверка `runner` заменена проверкой
`liquibase`.

**Migration**: Заменена требованием «Статус проверяет среду исполнения» в этом же изменении.

### Requirement: Отказ не меняет закрытую операцию

**Reason**: Сценарий «Раннер недоступен» устарел: откат попытки требует не раннера, а Liquibase.

**Migration**: Заменена требованием «Отказ от операции не меняет закрытую операцию» в этом
же изменении.

## ADDED Requirements

### Requirement: Статус проверяет среду исполнения

`forge status` MUST проверять подключение к целевой БД из `FORGE_DB_*`, вхождение БД в
`FORGE_TEST_DB_ALLOWLIST`, доступность Liquibase с драйвером и корректность корня принятого
состояния из `FORGE_ACCEPTED_DIR`. Любая непройденная проверка SHALL давать код `2`, а ответ
MUST называть каждую проверку и её итог. Проверка `accepted` MUST называть итоговый путь корня.

#### Scenario: Liquibase недоступен

- **WHEN** БД доступна и входит в перечень, корень принятого состояния корректен, а Liquibase или драйвер не найдены
- **THEN** команда возвращает код `2`, проверка `liquibase` отмечена непройденной, остальные — пройденными

#### Scenario: Среда в порядке

- **WHEN** все четыре проверки пройдены
- **THEN** команда возвращает код `0`

#### Scenario: Корень принятого состояния назван

- **WHEN** `FORGE_ACCEPTED_DIR=.forge/db`, а остальные проверки пройдены
- **THEN** проверка `accepted` пройдена и называет путь `.forge/db`, команда возвращает код `0`

#### Scenario: Корень вне проекта

- **WHEN** `FORGE_ACCEPTED_DIR=../db`
- **THEN** проверка `accepted` не пройдена, команда возвращает код `2`

### Requirement: Отказ от операции не меняет закрытую операцию

Операцию со статусом `success` или `failure` команда `forge abandon` SHALL NOT менять: код `1`.
Повторный отказ от брошенной операции SHALL возвращать код `0` и ничего не менять. Нечитаемый беклог
и ошибки окружения MUST давать код `2` без изменения статуса.

#### Scenario: Закрытая операция

- **WHEN** `forge abandon` вызвана для операции со статусом `success`
- **THEN** команда возвращает код `1`, беклог и корень принятого состояния не изменены

#### Scenario: Повторный отказ

- **WHEN** `forge abandon` вызвана для операции со статусом `abandoned`
- **THEN** код `0`, беклог не изменён

#### Scenario: Liquibase недоступен

- **WHEN** откат накатанной попытки требует шлюза, а Liquibase или драйвер не найдены
- **THEN** команда возвращает код `2`, статус операции прежний
