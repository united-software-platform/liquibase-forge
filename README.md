Liquibase Forge строит модель данных PostgreSQL по намерению, сформулированному агенту, проверяет её
накатом, сверкой и откатом и принимает в `db/` вашего проекта. Здесь — путь от установки до первой
принятой модели; другие задачи — в [документе кейсов](./docs/use-cases.md), правка самого forge —
в [`CONTRIBUTING.md`](./CONTRIBUTING.md).

## Что нужно

- [mise](https://mise.jdx.dev/) — единственный менеджер окружения: инструменты и координаты forge
  объявляются в `mise.toml` вашего проекта.
- Харнес с навыками формата Agent Skills — ZCode, Claude Code или другой, читающий навыки из каталога.
- Сервер PostgreSQL. Внутри workspace это общий экземпляр: проект объявляет только имя своей базы.
  Вне workspace сервер объявляет сам проект — [кейс 18](./docs/use-cases.md#кейс-18-хочу-поставить-forge-в-проект-вне-workspace).
- Доступ в сеть при первой подготовке: CLI загружает драйвер PostgreSQL для Liquibase.

## Шаг 1. Установить плагин и CLI

Плагин ставится из маркетплейса репозитория вместе со своей зависимостью — плагином `backlog`
проекта formular: навык `forge` порождает и исполняет беклоги операций навыками `backlog`.

**ZCode.** Откройте **Plugin Marketplace → Add → Add Plugin Marketplace** и вставьте адрес
репозитория: `https://github.com/united-software-platform/liquibase-forge.git`. Затем
в **Personal → liquibase-forge** установите **Liquibase Forge** и **Backlog (formular)**.

**Claude Code.** В REPL выполните:

```text
/plugin marketplace add united-software-platform/liquibase-forge
/plugin install forge-plugin@liquibase-forge
/plugin install backlog@liquibase-forge
```

Перезапустите сессию: навыки плагина появляются после перезапуска.

CLI `forge` ставится изолированным инструментом и не зависит от `pyproject.toml` вашего проекта.
Версию возьмите на странице [Releases](https://github.com/united-software-platform/liquibase-forge/releases)
репозитория:

```bash
uv tool install "liquibase-forge @ git+https://github.com/united-software-platform/liquibase-forge@vX.Y.Z"
```

Плагин и CLI выпускаются одним тегом — ставьте CLI той же версии, что плагин. Версию установленного
CLI показывает `uv tool list`; другая версия ставится той же командой с другим тегом.

Плагин и установка не меняют ни одного файла вашего проекта: координаты и секреты вы объявляете
сами на следующем шаге.

## Шаг 2. Подготовить окружение

Объявите в `mise.toml` вашего проекта инструменты и координаты forge, а секреты положите в `.env`:

```toml
[tools]
uv = "0.12.7"
java = "temurin-21.0.13.1+2.0.LTS"
liquibase = "5.0.4"

[env]
_.file = ".env"
FORGE_DB_NAME = "shop_forge"
FORGE_TEST_DB_ALLOWLIST = "localhost:{{ env.PG_PORT | default(value='5432') }}/shop_forge"
```

```bash
# .env — не коммитится
FORGE_DB_USER=forge
FORGE_DB_PASSWORD=<пароль роли forge>
FORGE_DB_ADMIN_USER=postgres
FORGE_DB_ADMIN_PASSWORD=<пароль суперпользователя сервера>
```

- **Имя базы** — своё у каждого проекта: на общем экземпляре проекты делят сервер, а не базу.
- **Адрес сервера** задавать не нужно: хост по умолчанию `localhost`, порт — порт общего набора
  из каскада mise, вне workspace — `5432`.
- **Администратор сервера** нужен, пока роль или база не созданы: от его имени `forge env up`
  их создаёт. Внутри workspace это учётные данные общего экземпляра.

В оболочке с активированным mise выполните:

```bash
mise install
forge env up
forge env check
```

`mise install` ставит инструменты; если mise не доверяет `mise.toml` проекта, он назовёт команду
`mise trust mise.toml`. `forge env up` создаёт на сервере роль и базу и кладёт драйвер Liquibase
в `.forge/lib/`; повторный запуск ничего не меняет. Действуйте по коду `forge env check`:

| Код | Что значит | Что делаю |
|-----|------------|-----------|
| `0` | Среда готова: база доступна и входит в перечень, Liquibase с драйвером на месте | Строю модель — шаг 3 |
| `2` | Какая-то из четырёх проверок не пройдена; ответ называет каждую с итогом и диагностикой | Устраняю причину по диагностике — [кейс 2](./docs/use-cases.md#кейс-2-хочу-подготовить-окружение-forge-с-нуля) |

Сервер должен быть запущен: внутри workspace это делает `mise run env-up`, вне workspace — задача
вашего проекта. После правки `.env` или `mise.toml` откройте новую оболочку: переменные читаются
при активации mise.

Подробнее — [кейс 2](./docs/use-cases.md#кейс-2-хочу-подготовить-окружение-forge-с-нуля),
[кейс 14](./docs/use-cases.md#кейс-14-хочу-использовать-forge-в-двух-проектах-workspace).

## Шаг 3. Построить модель

Опишите агенту нужную модель через навык `forge`:

```text
/forge Справочник клиентов: id, email, имя
```

Модель описывает таблицы и колонки с типами, первичный ключ, обязательность (NOT NULL), наборы
уникальности, внешние ключи между таблицами, автоинкремент колонки и перечень допустимых значений;
что из этого можно попросить — в [docs/model-format.md](./docs/model-format.md). Связь,
автоинкремент и перечень называйте в намерении прямо:

```text
/forge Заказы: id — автоинкремент, клиент — ссылка на справочник клиентов, сумма, дата заказа,
источник — одно из collector, manual
```

Навык начинает операцию по намерению, исполняет её беклог до подтверждённой модели или трёх неудач
и возвращает итоговый отчёт. При успехе модель и changelog принимаются в корень принятого состояния
`FORGE_ACCEPTED_DIR` — по умолчанию `db/`.

По умолчанию режим `interactive`: навык останавливается на стоп-знаках перед созданием модели,
накатом и закрытием и ждёт вашего решения. Ключ `--mode auto` заменяет стоп-знаки автоматическими
гейтами.

Строки справочных таблиц принятой модели заполняет тот же навык с ключом `--seed`; при успехе
в корень принятого состояния принимаются `seed.yaml` и changelog данных:

```text
/forge --seed "статусы заказа: черновик, оплачен, отменён"
```

Подробнее — [кейс 3](./docs/use-cases.md#кейс-3-хочу-продолжить-остановленную-операцию),
[кейс 11](./docs/use-cases.md#кейс-11-хочу-понять-почему-операция-закрылась-с-failure),
[кейс 13](./docs/use-cases.md#кейс-13-хочу-бросить-открытую-операцию),
[кейс 15](./docs/use-cases.md#кейс-15-хочу-заполнить-справочник),
[кейс 16](./docs/use-cases.md#кейс-16-хочу-убрать-справочник-из-модели).

## Шаг 4. Закоммитить результат

Коммит делаете вы. Итоговый отчёт называет в `commit.files` файлы для коммита: след операции
`backlog/forge-model/<штамп>/` и беклоги попыток `backlog/forge-apply/<штамп>-<N>/`, а при успехе —
и принятое состояние. След объясняет, как получена модель, а после неудачи или отказа — почему
схема не изменилась.

Коммитьте файлы и каталоги из `commit.files`, а не всё рабочее дерево (`git add -A`): след
остановленной операции и беклоги других операций `formular` в `backlog/` тоже видны git, но в коммит
этой операции не входят.

> **Внимание:** если по рекомендации плагина `formular` в `.gitignore` вашего проекта есть строка
> `backlog/*`, удалите её — иначе след не попадёт в коммит.

Подробнее — [кейс 10](./docs/use-cases.md#кейс-10-хочу-накатить-принятые-изменения-на-бд-своего-приложения).

## Ограничения

- **CLI один на машину.** `uv tool install` ставит одну версию `forge` на пользователя: разным
  проектам нужны одна версия плагина и CLI.
- **Харнес без маркетплейсов плагинов.** Навык `forge` подключается ссылкой на
  `plugins/forge-plugin/skills/forge` клона репозитория; плагин `backlog` — по инструкции formular.
- **Только PostgreSQL и схема `public`.** Сверка видит таблицы, колонки, первичные ключи, наборы
  уникальности, перечни значений и FK; представления и индексы вне модели, а `CHECK` выражается
  только перечнем значений одной колонки —
  см. [docs/reconciliation.md](./docs/reconciliation.md#ограничения-и-допущения). Внешний ключ
  создаётся с действием `NO ACTION`: `ON DELETE`, `ON UPDATE` и отложенные ограничения
  (`DEFERRABLE`) не поддерживаются — см. [docs/model-format.md](./docs/model-format.md#ограничения-и-допущения).
- **Смена типа, NULL и первичного ключа не поддерживается.** Такую модель `forge generate`
  отклоняет, переименование выражается удалением и добавлением —
  см. [docs/migration.md](./docs/migration.md#неподдерживаемые-изменения).
- **Удаление теряет данные.** Откат удаления восстанавливает структуру, но не данные; в режиме
  `auto` удаления требуют ключа `--allow-drop` —
  см. [docs/operation.md](./docs/operation.md#согласие-на-удаления).
- **Новая колонка NOT NULL в справочнике с данными недоступна.** Если у таблицы есть строки
  в принятом seed, `forge generate` отклоняет такую колонку конфликтом `not_null_column_added`:
  добавьте колонку, допускающую NULL, и заполните её операцией seed —
  см. [docs/operation.md](./docs/operation.md#согласование-с-принятым-seed).
- **Не больше трёх попыток и одной открытой операции.** Закрытую операцию отменить нельзя —
  см. [docs/operation.md](./docs/operation.md#ограничения-и-допущения).
- **Шаблоны операций не настраиваются под проект.** Они лежат в плагине и всегда соответствуют
  его версии; изменение шаблона — предложение в репозиторий forge.
- **Liquibase 5.x распространяется под лицензией FSL**, а не Apache 2.0. FSL ограничивает только
  конкурирующее коммерческое использование Liquibase.
- **Корень следа — только `backlog/`.** `BACKLOG_ROOT` для операций forge не поддерживается: шаблоны
  называют пути следа литералами.
